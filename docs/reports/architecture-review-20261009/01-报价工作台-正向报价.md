# 01 · 报价工作台（正向报价）

## 1. 产品侧

### 1.1 六步流水线

报价不是「填一张表」，而是**六个角色交替的步骤卡**（`cpq_wf.py:35` `QUOTE_STEPS`）：

| 步 | 名称 | 主责角色 |
| --- | --- | --- |
| 1 | 确认需求配置 | 销售经理 |
| 2 | 工艺确认 | 工艺经理 |
| 3 | 定价-利润加成 | 销售经理 |
| 4 | 报价-其他加价项 | 销售经理 |
| 5 | 报价方案 | 销售经理 |
| 6 | 输出报价单 | 销售经理 |

销售在第 1 步录入需求，卡片交给工艺经理；工艺确认完回到销售，销售做定价、加价项、方案，最后出报价单。每一步都是可回看、可留痕的快照。

### 1.2 三条「支线」而不是一路向前

流程里有两处**不能直接推进**，设计成支线（报价卡片留在原步骤等结果）：

- **第 1 步匹配不到合适标品**（`cpq_match` 最高分 < 70）→ 不是硬凑，而是请工艺经理去技术工艺**新建产品**（`tech_new_product`）。产品出来后再回到第 1 步。
- **技术工艺 2.2 做完工艺与参数后，成本不由工艺经理算** → 交财务经理测算（`tech_cost`），测完退回工艺经理复核；有问题就改工序/用量。

这条设计的业务含义：**责任边界不许越位**——工艺不动财务的价，财务不改工艺的工序。

### 1.3 需求输入

销售可以贴文字、传 Excel/PDF/Word/图片，系统抽取结构化需求。抽取有几条硬规则（近两周边际收敛的）：

- 只从**明确标注且不歧义**的原文里提取盒型编码、盒族、闭合方式、内尺寸、面纸克重、内托、V 槽、数量。
- **只填空字段**，不覆盖人工已填和 CAD 已填的值；每个字段留 `user_text` 来源 + 原文证据 + 待确认标记。
- 同义表达要等价：`225g面纸` / `面纸225g` / `双开门` / `对开`。
- 原文与 CAD 值冲突时**两边证据都留、标冲突**，不静默覆盖。

### 1.4 正式报价的「最后一公里」

导出 Word 和写入业务库（`_build_quote_docx` / `_import_quote`）都有**服务端门禁** `_assert_formal_packaging_quote`：没有原会话号、原会话不是包装、成本包有缺口、成本证据有问题、报价仍是草稿/被标 publish_blocked/还有 gap_count —— 一律拒绝，返回 `formal_quote_blocked`。

产品含义：**「带缺口草稿」可以内部预览、可以继续往下填，但导不出正式报价单、写不进业务库。**

### 2.2 数据形状

- **步骤快照**：`cpq_wf.step_snapshot(sid, n)` → 该会话第 n 步的 `data`。门禁只读这个，**不做推断、不补默认值**。
- **报价版本**：第 5 步确认时把当次报价落成一版（`QUOTE_VERSION_STEP = 5`），第 6 步与导出消费同一版。
- **包装交接包**：第 2 步写 `packaging_package`（盒型、成本、缺口、结果版本），是包装链路的事实源。

### 2.3 关键决策与原因

| 决策 | 原因 |
| --- | --- |
| 门禁做成**纯函数** `cpq_quote_gate.py`，被多处调用 | 原来门禁散在 1839 行的 `cpq_agent_server.py` 里、只有一处生效；抽出来后 Agent API 与卡片写接口共用同一条判据 |
| 包装走**独立定价**，不进电池/通用规则 | 包装的成本结构（材料/模切/糊盒/运费/模具/版费）与电池完全不同，硬套会算错 |
| 门禁**只看已落地数据** | 「前端填满」「模型说填好了」都不能代替服务端判据 |
| 抽取**只填空字段 + 留证据** | 报价数据要能回溯到原文，出问题能查是谁的锅 |

## 3. 已知缺口

- 需求抽取的**同义词覆盖不全**，Spec 自己写了「其他产品名同义词并非全部覆盖」。
- 包装「带缺口草稿」与「正式报价」之间目前靠门禁拦，**没有面向销售的进度可视化**（现在只有首页卡片上的文字提示）。
- 第 3–5 步的金额口径历史上出现过「两位显示值再乘数量」的舍入问题，已在 10-8 修（明细改为同一报价版本的展示投影），但这类「显示精度 vs 计算精度」的坑**没有被一条全局不变量钉死**。
