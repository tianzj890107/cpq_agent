# 03 · 报价与技术工艺桥接、成本与财务交接

## 1. 产品侧

这条线回答一个业务问题：**销售报的价，和工程师算的成本，怎么对上？**

```
报价第 2 步（工艺确认）
   → 生成「包装交接包」packaging_package：盒型、尺寸、材料、成本、缺口、结果版本
   → 技术工艺按项目接手：零件 → BOM → 工艺路线 → 成本
   → 成本结果回传报价第 5 步，形成「产品行」（基础成本 + 暂估标记）
   → 第 6 步出正式报价单
```

角色分工与门禁：

- 工艺经理确认参数与工艺（2.1–2.2），**成本不由工艺经理算**，交财务经理（2.3）。
- 财务测完退回工艺经理复核（有工艺问题就改工序/用量，不是财务改价）。
- 成本有缺口时：可以走**「带缺口的内部草稿」**继续往下（销售能预览），但**正式导出/写业务库会被服务端拦住**。

## 2. 技术侧

### 2.1 桥接的三段

| 段 | 文件 | 作用 |
| --- | --- | --- |
| 报价 → 技术 | `cpq_tech_bridge.py`（1384 行） | 把报价会话落成技术工艺能读的快照。`packaging_snapshot()` 产出 `s2_products`（产品行）、`s2_packaging`（盒型与参数）、`s2_packaging_cost`（成本构成） |
| 技术内部 | `tech_app/backend/services/integration.py` | 参数推荐、工艺轮廓、成本分析；`send_to_finance()` 是交财务的出口 |
| 技术 → 报价 | `FINANCE_HANDOFF_FIELDS`（`cpq_agent_server.py:3834`） | 回传字段白名单：`business_case_id` `quote_session_id` `tech_project_id` `source_task_id` `industry` `quantity` `unit_cost` `currency` `cost_status` `gap_count` `cost_fingerprint` `provisional` |

**字段白名单的意义**：缺什么就进 `missing` 明说，**不猜数**；报价侧据此落产品行（基础成本 + `provisional` 暂估标记）。

### 2.2 包装成本的「唯一计件对象」

这是近两周最重要的一次口径统一（10-1 上线，10-8 继续加固）：

- `cost_review.ir_from_packaging_parts()` 优先读 `business_parts`（业务件），没有再回退 `parts`（几何分量）。
- `cost_review.parts_source()`：**包装行业只认业务件**，业务清单为空或读取失败时**不回退到几何碎片**（不允许「263 个碎片冒充清单」）。
- 单件成本：包装走 `packaging_parts.load_part_cost(project_id, part_id)`，并且要**校验业务件哈希**（`business_parts_hash` 对不上就当作没有成本，防止旧版本成本被当成新的）。
- 单件只显示**材料费**，不套通用电池系数（`cost_scope = "material_only"`）。
- 整单：走 `packaging_cost.load_cost()` 的确定性公式，**不重复叠加零件材料费**，`ready` 还要求 `has_gaps == False`。
- `manufacturing_snapshot.packaging_snapshot()` 把零件文档换成业务件文档，让制造快照和成本页看到同一份事实。

### 2.3 内部草稿财务交接

`integration.send_to_finance(..., draft=True)` → `_send_packaging_finance_draft()`：

- 仅包装可用（其它行业直接报错）；
- 载荷带 `project_id`、需求事实、`business_parts_hash`、工艺路线；
- 结果标 `draft=True`，`confirmed / params_confirmed / process_confirmed` 全为 `False`，`waivers` 为空；
- 写审计 `packaging_finance_draft_handoff`；
- **不代签参数/工艺确认，不开放正式发布。**

### 2.4 关键决策与原因

| 决策 | 原因 |
| --- | --- |
| 回传用**字段白名单**而不是自由 dict | 防止「顺手多传一个字段」把口径带歪；也便于对账 |
| 成本回传必须带 `cost_fingerprint` + `provisional` | 报价侧要能判断「这个成本是哪一版算的」「是不是暂估」 |
| 包装单件 / 整单**两套口径分开** | 单件是材料费；整单是确定性公式（含模具、版费、运输等），二者相加就是重复计费 |
| 业务件哈希对不上就**当作没有成本** | 宁可显示缺口，也不显示过期价 |
| 有缺口允许**草稿**但拦住正式导出 | 演示/内部评审要能走通，但不能骗客户 |

## 3. 已知缺口

- 桥接字段是白名单，但**没有版本号**：`FINANCE_HANDOFF_FIELDS` 变了以后，历史回传数据没有标记。
- 「缺口」的口径分散在 `cost_review`（`missing` / `has_gaps` / `zero`）、`packaging_cost`（`has_gaps`）、`integration`（`gaps`）三处，**没有单一真值来源**，靠约定一致。
- 真实待办与销售回传需要上线复验（Spec 自己写了「真实待办及销售回传需上线复验」）。

## 4. 可优化项（供拍板）

### 产品侧

| 优化 | 收益 | 代价 | 风险 | 我的建议 |
| --- | --- | --- | --- | --- |
| 回传产品行上直接显示「成本版本 + 是否暂估 + 缺口数」 | 销售一眼知道这价能不能用 | 小（字段已有） | 低 | **建议做** |
| 财务测算完成后，给销售一条明确通知 | 现在靠人去点卡片 | 中等 | 低 | 建议做，和任务通知体系统一 |
| 「缺口」在页面上按「缺材料价 / 缺用量 / 缺尺寸」分类展示 | 工程师知道去补什么 | 中等 | 低 | 建议做，Spec 里已有分档原始字段 |

### 技术侧

| 优化 | 收益 | 代价 | 风险 | 我的建议 |
| --- | --- | --- | --- | --- |
| 把「缺口」收敛成**单一 truth 源**（一个纯函数，其它模块只读） | 根治三处口径漂移 | 中（要动 cost_review / packaging_cost / integration） | 中 | **建议做**，收益明确 |
| 回传协议加 `handoff_version` | 历史数据可解释 | 小 | 低 | 建议做 |
| 单件成本哈希校验扩展到工艺路线与 BOM（同样防旧版本） | 一致性 | 中 | 低 | 建议做 |
