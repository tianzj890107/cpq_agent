# 05 · DWG → DXF → CAD IR 解析

## 1. 产品侧

### 1.1 用户看到的是什么

工程师在 2.1 上传 `.dwg`（或已转好的 `.dxf`），页面启动「包装图纸八步」：

```
① 文件预检 → ② DWG 转换 → ③ CAD IR 解析 → ④ 包装语义
→ ⑤ 零件提取 → ⑥ 字段回写 → ⑦ 待确认 → ⑧ 下游准备
```

跑完后能看到：图层角色、成品轮廓候选、尺寸候选、几何零件（连通分量）、业务部件（待确认）。

### 1.2 真实水位（截至 2026-10-09）

两份真实样本（生产用 ODA 27.1 主转换器，非回退）：

| 样本 | 实体数 | 图层数 | 几何零件 | 闭合比例 |
| --- | --- | --- | --- | --- |
| 酒盒 | 6711 | 8 | 263 | 0.510 |
| 圆盘盒 | 3457 | 32 | 312 | 0.840 |

「八步 8/8 completed」只代表**编排跑完**，不代表零件正确：酒盒 263 个几何分量对应业务上二十几件，圆盘盒 312 个对应五十几件。

### 1.3 转换器的商业含义

DWG 是 Autodesk 的私有格式，合法转换依赖 **ODA File Converter**（有许可问题）。所以：

- 门禁里 `converter_license`（转换器许可与部署方式已由业务/法务确认）是**人工项**，系统不代签；
- 能力声明固定为「**DWG 编排能力完成，真实转换能力未验收**」，不含「已获得正版许可」；
- 回退链默认**关闭**：没显式配 `DWG_CONVERTER_FALLBACK_PROVIDER` 就没有回退，避免「悄悄用了另一个转换器还显示成功」。

## 2. 技术侧

### 2.1 三段职责

| 段 | 文件 | 要点 |
| --- | --- | --- |
| 文件预检 | `services/file_preflight.py` | 后缀、大小、magic、可读性；不通过就不进转换 |
| DWG 转换 | `services/cad_converter/`（`service.py` + `adapters/`） | 主转换器 + 受控回退链；输出 `dxf` + `preview`；产出审计与 `converter_role` |
| CAD IR 解析 | `services/cad_ir/`（`parser.py` `geometry.py` `blocks.py` `units.py` `model.py` `persistence.py`） | 把 DXF 抽成结构化 IR：实体、图层、块、文字、尺寸标注、extents、单位 |

### 2.2 转换器配置（34 上的实际取值）

环境变量都是 `DWG_CONVERTER_*`（`service.py:48`）：

| 变量 | 34 实际 | 说明 |
| --- | --- | --- |
| `PROVIDER` | `oda` | 主转换器 |
| `BINARY` | `/home/data/cpq-tools/oda-file-converter-27.1/squashfs-root/AppRun` | |
| `VERSION` | `27.1` | 与现场一致才 `version_ok` |
| `WRAPPER` | `xvfb-run -a` | ODA 需要 X 显示 |
| `FALLBACK_PROVIDER` | `libredwg` | 回退（默认关闭，显式配置才启用） |
| `FALLBACK_BINARY` | `/home/data/cpq-tools/current/bin/dwg2dxf` | |

配置写在**仓库外**的 env 文件（34 上 `/home/wugefei/CPQ/cpq_env.sh`，权限 0600），不写进仓库。

### 2.3 一个必须记住的坑：`PATH`

`xvfb-run` 是个 shell 脚本，会**按名字**去调同目录的 `Xvfb` / `xauth`。所以那个目录必须在 **8010 进程的 `PATH`** 里。

但把 `PATH` 写进 env 文件**对服务无效** —— 启动器读配置时用的是 `load_dotenv(override=False)`，`PATH` 本来就在进程环境里，于是文件里那一行被静默忽略。34 上因此漏过一次：ODA 启动即崩、**静默回退 LibreDWG**，而页面只表现为「不是位图，请传 PNG」。

这就是为什么：

- 部署脚本的启动命令里必须带 `PATH="/home/data/cpq-tools/xvfb-user/root/usr/bin:$PATH"` 前缀；
- 部署脚本第 5 步**真转两份样本**并核对 `converter_role=primary`、`fallback_used=false` —— 只看 `status=ok` 是不够的，回退顶上时 `status` 一样是 ok；
- `dwg_conversion_smoke.py` 见到 `fallback_used=true` 直接判「主转换器未生效」。

### 2.4 CAD IR 的形状

以酒盒为例（隔离跑的真实结果）：

- `entities = 6569~6711`，`layers = 8`；实体类型分布 `LINE 5598 / DIMENSION 316 / ARC 311 / SPLINE 310 / ELLIPSE 21 / HATCH 11 / LWPOLYLINE 2`。`DIMENSION=316` 与 `layers=8` 与金标逐项一致 —— 这是**解析保真度**的锚点。
- IR 保留：实体 ID、类型、图层、块路径、坐标/顶点、闭合标志、曲线度量（半径/弧角/椭圆比/bulge）、文字与 MTEXT 富文本、尺寸标注与目标。
- `units.py` 负责单位判定；单位未确认时**不写数值**（下游会看到「未知」而不是错的数）。
- 曲线处理是近两周重点：**完整圆、跨零度圆弧、椭圆、带 bulge 折线必须保留曲线形状，不得以端点弦代替圆弧**；采样有误差与点数上限。

### 2.5 关键决策与原因

| 决策 | 原因 |
| --- | --- |
| 转换器**可插拔**（adapter + 受控回退链 + manifest） | 许可未定，不能把代码绑死在一个转换器上；同时禁止「静默降级」 |
| 回退默认**关闭** | 「悄悄回退却报成功」比直接失败更危险 |
| 产物落盘 + 审计 + `converter_role` | 事后能回答「这份 IR 是谁转的、哪一版」 |
| IR 只描述**图元事实**，不做业务判断 | 业务判断放在语义层，便于替换规则 |
| 曲线保形而不是折线近似 | 圆盘盒/圆角盒的轮廓与尺寸都依赖真实圆弧；近似会让面积、外接矩形、闭合判定全错 |
| 单位未确认不写数值 | 宁可「未知」，不可「错数」 |

## 3. 已知缺口

1. **真实转换能力未验收**：门禁 `real_samples_e2e_passed` 未签，实际是「本地有两份样本能跑通」，不等于生产图库普遍可用。
2. 三维能力：适配器声明**不支持导出三维中间格式**（`three_d.supported=false`），3D 视图区因此不成立（产品上已决定 2.1 用 2D 平面图）。
3. 解析保真度只在**两份样本**上有金标比对（`entities`/`layers`/`DIMENSION`），其它图没有金标。

## 4. 可优化项（供拍板）

### 产品侧

| 优化 | 收益 | 代价 | 风险 | 我的建议 |
| --- | --- | --- | --- | --- |
| 2.1 页面直接显示「本次转换由谁完成（主/回退）+ 版本」 | 现场一眼看出是否踩了 PATH 坑 | 小（数据已有） | 低 | **建议做** |
| 上传页对 `.dwg` 明确写「需要 ODA 许可，当前为受控试用」 | 避免销售误以为已获授权 | 小 | 低 | 建议做 |
| 给出「哪些图能跑、哪些图会降级」的样例集说明 | 降低期望落差 | 中 | 低 | 建议做 |

### 技术侧

| 优化 | 收益 | 代价 | 风险 | 我的建议 |
| --- | --- | --- | --- | --- |
| **扩金标样本集**（从 2 份到覆盖常见盒型） | 唯一能提升「真实转换能力」结论的路径 | 需人工标注，成本最高 | 低 | **建议做**，这是当前最大的能力瓶颈 |
| 把 PATH/环境陷阱做成**能力隔离**（不是 fail-fast 全停）：部署验收失败阻止发布；运行时转换器故障只禁用 DWG 解析并明确告警，登录/历史报价/文字快速报价仍可用 | 根治部署类事故，又不让一个能力故障拖停整站 | 中 | 中 | 建议做；门禁里已有 `converter_chain_configured` 可承载（对应 `10` 的 `T8`） |
| 曲线采样参数（误差/点数上限）提到配置并记录到 IR 元数据 | 换参数后可复现 | 小 | 低 | 建议做 |
