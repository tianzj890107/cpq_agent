# 07 · 排版排模、BOM、工艺路线与成本

## 1. 产品侧

### 1.1 三个阶段各自的产出

| 子步骤 | 产出 | 关键约束 |
| --- | --- | --- |
| 3.1 方案与部件 | 业务部件清单（从图纸推导，待确认） | 一件可由多个 CAD 片段组成；同件只计一次 |
| 3.2 排版排模 | 排模记录（「各排 2 模」「纸张 860×460mm」） | **排模不是零件**；未确认的排模不进成本 |
| 3.3 后道加工与组装工艺 | 工艺路线（模切、糊盒、装配、检验…） | 缺组成/尺寸/费率不伪造完整总额 |
| 4.1 / 4.2 / 4.3 | 零件成本 / 组装成本 / 汇总 | 单件只算材料费；整单走确定性公式 |

### 1.2 「一件 = 多片」是常态

一个业务件（比如「左盖面纸」）在图纸里可能是几个**不相连**的闭合片段；反过来，一个片段也可能只是该件的一层材料。产品上的要求：

- 每片的 CAD ID、图层、矩形、是否已确认都保留；
- 不用「并集矩形」冒充零件外形（并集会画出一个不存在的形状）；
- 不因多片而把 BOM 数量重复计；
- 排版实例只是用量/版位证据，不是新增业务零件。

### 1.3 报价数量 vs 装配用量

成本里有两个「数量」，必须分开：**报价批量**（客户要多少）与**单件装配用量**（一件成品用几个）。历史上混用过；现在数量不一致会变成**确认缺口**，而不是自动取一个。

## 2. 技术侧

### 2.1 文件与职责

| 文件 | 职责 |
| --- | --- |
| `packaging_layout.py` | 排模记录：`layout_record`（清洗 CAD 富文本但保留 `raw_text`）、`extract_layout_rows`、`scheme_labels`、`is_layout_instruction`、`declared_sections`（复合名拆组成）、`part_fragments`（多片段）、`set_layout_confirmation` / `set_layout_assignment`（确认与关联，带审计） |
| `packaging_sections.py` | 组成（section）层：`physical_groups`（按轮廓与内孔做物理分组）、`hydrate_part`、组成缺口 |
| `packaging_bom.py` | `build_bom()`：模板展开（`expand_parts`）+ 装配（`_assemble`）；行来源有 `kb_packaging_part_template`（模板）/ `dwg_parts`（几何回填）/ 第三类（见 `packaging_bom.py:72`）；绑定留痕 `size_source.dwg_binding`（含 `rule_id`）；绑不上的行保持 `needs_input` 并在 gaps 给 `part_size_unbound:<part_code>` |
| `packaging_route.py` | 工艺路线：步骤名归一化 `normalize_step_name`、必填表面步骤 `required_surface_steps`、模板步骤 `_template_step`；合并保留组成归属并重编号依赖 |
| `packaging_formula.py` | **确定性公式引擎**：`normalize_expression` → `_tokenize` → `_Parser.parse()` → `_calc` → `evaluate(expr, variables, precision)`；白名单函数 `ALLOWED_FUNCTIONS`；`_guard_characters` 防注入 |
| `packaging_cost.py` | 包装成本：公式目录 + 变量映射 + 受控求值（`:940`）、最小收费口径（`minimum_charge_policy`）、用量（`_part_usage_qty`）、`verbatim_compare` / `verbatim_equivalent`（把**变量映射后的**引擎表达式与源表公式做等价比对） |

### 2.2 公式引擎怎么和模型分工（重要）

**它们不分工，是分开的。** 成本计算里没有模型调用：

- 每条成本表达式登记 `variable_map`（语义名 → 表列字母）与 `source_formula`（原始单元格公式）；**源公式、变量映射、计算参数三者分开披露**——映射后与源表等价，不等于「逐字照抄」，也不等于材料价/单位/数量一定正确；
- 求值是纯函数，带精度参数（`evaluate(..., precision=1)`）；
- **`verbatim_compare` 把「变量映射后的引擎表达式」与源表公式做等价比对** —— 这是「公式结构与源表一致」的证据（前提是映射正确；它不覆盖材料价、单位、数量、排模参数）；
- 模型只在**上游**出现：推荐零件名、判文字语义、推荐工序；它给的东西必须能被确定性链验证，不能直接进价。

这条设计是整个系统最值得保留的部分：**报价的钱是算出来的，不是模型说出来的。**

### 2.3 关键决策与原因

| 决策 | 原因 |
| --- | --- |
| 排模与业务件**分成两种事实** | 「各排 2 模」是版位不是件；混算会让 BOM 多出零件 |
| 一件多片保留每片信息（`cad_fragments`） | 并集矩形会画假轮廓、算假尺寸 |
| 成本公式登记 `source_formula` + **映射后等价比对** | 客户表的公式是权威口径；但真实存在的改写口径必须显式登记，不能笼统宣称「逐字抄」 |
| 最小收费（起订价）单独立口径，**已裁决为 `sheet_labor_rate`（工费率）** | 三条候选无法同时满足早期 c1/c2/c4；裁决人 张真 / 2026-09-21，冻结值归零后只作证据保留 |
| 数量不一致 → 缺口而不是自动取值 | 猜错数量 = 猜错总价 |
| 排模未确认不进成本 | 用量没定就没法算材料费 |
