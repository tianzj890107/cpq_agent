# 08 · 知识库、DA 本体与主数据

## 1. 产品侧

### 1.1 知识库在业务上是什么

系统里有两类「知识」：

- **口径与规则**：匹配权重、零件模板、材料映射、成本公式与费率、物流规则 —— 这些决定「系统怎么算」；
- **主数据**：物料、供应商、设备、工序、标准件、DA 本体（行业数据模型）—— 这些决定「系统认识什么」。

产品规则：**口径与规则必须可追溯到来源**。所以每条规则都带 `source_type` 和审核状态，界面上会显式区分：

- `workbook` / `dwg_confirmed`：权威（来自客户工作簿或图纸确认）；
- `demo`：演示数据 —— **能算出数，但每行都会带「仅供流程演示，出价前必须换成权威费率」的告警**。

### 1.2 一个现实约束

知识库上线有预检：源库（`tech_app/tech_data/da.db`）如果只有 20 张基础表、9 张包装表一张都没有，直接导入只会建出**9 张空表**，预检判 `empty_required_table`。演示数据灌进生产会变 `demo_only` → **no-go**。

产品含义：**这个系统「能不能出数」取决于有没有权威数据，而不取决于代码写完没有。** 这也是为什么很多功能在代码侧完成、在数据侧还走不通。

## 2. 技术侧

### 2.1 PG 知识库（`cpq_kb.py`，1254 行）

- 库：`cpq_kb`，共 **32 张表**（含 9 张 `kb_packaging_*` + 3 张 `kb_quick_quote_*`；以 `cpq_kb.py` 的 `KB_TABLES` 实际条数为准）——本条已在 10-9 复核中由「30 张」订正。
- **表名与顺序是快照契约**：前 20 张的顺序被 `tests/test_packaging_kb_authoritative_rollout_red.py` 冻结，「只能追加」。
- 每张表有业务主键 `KB_KEYS`（与 `da_schema.sql` 的 PRIMARY KEY / UNIQUE 一致），导入器靠它做幂等 upsert。
- 台账：`kb_meta`（表级元信息）、`kb_version`（版本）。

关键表分组：

| 组 | 表 |
| --- | --- |
| 基础 20 张 | `kb_component*`、`kb_standard_part`、`kb_equipment_class`、`kb_process_*`、`kb_inspection_item`、`kb_material*`、`kb_supplier*`、`kb_cost_rate`、`kb_cost_factor` |
| 包装扩展 9 张 | `kb_packaging_box_type`、`_part_template`、`_process_template`、`_insert_accessory`、`_cost_formula`、`_logistics_rule`、`_match_weight`、`_cost_content`、`_tooling_rule` |
| 快速报价 3 张 | `kb_quick_quote_config`、`_match_weight`、`_delta_rule` |

快速报价的读法很硬：**表读不到或为空就直接报错，不回落代码里的种子值**（`load_weights()` / `load_rules()`）——「不编价」。

### 2.3 DA CLM 工艺路线真实接入（`## 534`，10-9，本地未提交）

这是最新一批，方向值得注意：**不再依赖本仓库的种子数据，直接读生产 PG**。

- 只读核实线上：**27 个头、124 行**；**26 个包装路线全部是草稿**；**所有行的三类工时为空**。
- 新增**内部令牌保护**的只读路线查询（`tech_app/backend/services/da_process_routing.py` + `cpq_process_routing.py`），技术侧通过 HTTP 读取；按产品编码或精确件名查询并关联工序，保留顺序、原文、来源、状态与空工时。
- 真实依据会加入模型工艺推荐输入并随结论保存；**名称/草稿不视为批准标准**，服务不可用明确披露，工序输出仍标「模型推荐」。
- 实测：左盖面纸（名称/编码）命中 8 道工序；圆盘盒名称无匹配。

### 2.4 关键决策与原因

| 决策 | 原因 |
| --- | --- |
| 表名与顺序做成**快照契约** | 下游脚本、预检、部署都按序号对账；顺序变了会静默错位 |
| 规则必须带 `source_type` 与审核状态 | 报价要能给客户，demo 费率混进正式价是事故 |
| 快速报价**表空就报错**，不回落种子 | 「悄悄用内置假数据出价」比报错危险 |
| DA 本体 md 与 xlsx 必须逐字一致 | 两个入口给不同答案会造成口径分裂 |
| 工艺路线读生产 PG 且**只读** | 主数据变更不归本系统；系统只消费不写入 |
| 空工时是**缺口**不是 0 | 0 会被算成「这道工序不花时间」 |

## 3. 已知缺口

- 知识库**数据未灌**（预检 7 项 `empty_required_table`）；仓库里的 seed 是 `source_type='demo'`。
- DA 工艺路线 **26 个包装路线全是草稿、工时全空** → 当前不能作为标准工时或正式成本依据（`## 534` 自己写了「不构成标准工时或正式成本验收」）。
- 圆盘盒名称在 DA 路线里**匹配不到**，说明命名口径与主数据尚未对齐。
