# 工艺推荐本地性能对比

## 结论

仅本地修改，未提交、推送或部署。工艺推荐前逐件检查已有结果的读取开销显著下降；未测真实模型整批生成时间，不承诺整个推荐过程加速97%。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 28件已有工艺读取，中位秒数 | 9.1015 | 0.2533 |
| 三轮秒数 | 9.1015 / 9.0783 / 9.6442 | 0.2444 / 0.3531 / 0.2533 |
| 同键3并发冷读候选的HTTP请求数（延迟桩） | 3 | 1 |

读取阶段减少约97.2%，约36倍。三并发HTTP本就可重叠，3→1只证明减少重复请求，不等于其墙钟时间减少三分之二。

## 测量边界与复现

- 隔离临时JSON后端；28件大CAD合成夹具，业务件文件26,258,950字节，每件8个候选且各1200个点。不是实际酒盒/圆盘盒项目，不读写用户项目或真实PG。
- 真正执行 `main.get_packaging_business_part_process`、版本检查及JSON后端。每种模式跑3轮。同一进程中将新投影读取替换为原全量读取作为对照，模型调用均为0。
- 所有模式、所有轮次的28件完整响应逐项相等；响应SHA256为 `fe825e2a2c367cd7663e7687d06282e3518d2c25c0dd94cc51edf8e7ec33549b`。
- 实现前独立基线三轮为9.0939 / 8.8851 / 9.0531秒，中位9.0531秒，与成对对照一致。
- DA并发测试仅对HTTP依赖注入80ms延迟；实跑线程、缓存、Future合并和失败重试。不将它当作线上数据库或模型测速。
- 复现：`./open-claude/.venv/bin/python -W ignore -m unittest tests.test_packaging_process_local_performance_red`。

## 实现

1. 单件工艺GET在缓存文档深拷贝前投影当前件与清单身份，不复制其他件及全图几何。所选件本身的所有字段保留，用于严格判断历史工艺可否复用。POST推荐仍读完整证据。
2. DA作用域缓存同键冷读合并，源地址与内部身份摘要加入键；不同键仍并发，等待方拿独立副本。失败唤醒所有等待方且不缓存，后续允许重试。TTL=0及作用域外仍不合并。
3. 不改变模型提示词/数量/并发，也未按名称或相似度复用别件模型结果。这样不因提速减少推荐信息或串用不同件工艺。

## 测试

- 实现前新增7项：4失败、2缺实现错误、1基准通过；其中同键冷读实测3请求而非1，原默认GET仍调用全量读取。
- 修改后9模块130项：126通过，4项旧多组成测试失败；额外6模块50项全部通过。合计180项执行，176通过。
- 4项失败在内存加载HEAD原始 `packaging_parts.py` 后逐项复跑，同一断言仍然失败；不是本轮提速引入，未修改这些断言。分别为：`test_pending_section_bom_never_falls_back_to_confirmed_parent_union`、`test_plain_name_group_excludes_layout_copies_and_is_translation_invariant`、`test_single_business_name_can_propose_multiple_owned_shapes`、`test_ui_section_gate_and_markup_keep_every_portion_without_untrusted_html`，均在 `test_packaging_multipart_sections_complete_red`。
- 旧整件工艺读回测试的模拟函数补充可接收新只读参数，原有历史工艺断言未放宽。Python编译和diff检查通过。

## 上线判断

本轮适合降低“开始推荐前读取旧结果”和并发查库压力；如果主要时间耗在首次逐件模型生成，这部分仍然存在，不能用0.25秒解释整批完成时间。真实网络、模型排队、冷文件缓存及POST输入准备仍需单独计时后决定下一批。当前没有启动服务、做浏览器手动验收或操作线上。
