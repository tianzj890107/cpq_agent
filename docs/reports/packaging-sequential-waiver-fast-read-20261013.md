# 需求顺序、成本签字与读取验收

2026-10-13。本地实现，未提交推送部署，未写线上项目。

## 改动

- 1.1、1.2、1.3不再要求提前完成2.1；状态和审批权限保留。
- 包装需求已提交/审核也可跑2.1。冻结字段另存packaging_engineering_fields，保留需求修订与IR哈希，不回退审核、不改客户字段。下游只读同版本confirmed工程证据补缺，不覆盖客户值。
- 前端公式缺口进入真实确认提示；用户点击仍要继续后发送空waiver也有效。后端先读取实际缺口和签字，再决定质量门禁；内部暂估可签字确认，对账/过期缺口保留，正式能力未放宽。
- 返回真实确认状态与签字，标记internal_estimate，状态投影不会又把4.1/4.2卡回未完成；内部提交工艺经理可以沿用覆盖当前缺口的签字。
- 包装成本GET跳过制造快照，不加载BOM/路线/图纸整包。确认请求读取一次公式成本视图，在门禁、签字和返回体中复用。成本先显示，会话回放后台进行。

## 证据

- 新Spec、最初6项红测实际全失败后实现；后续工程证据、状态请求缓存及读取超时红测亦实际失败后实现。新专项现14项。
- 实际执行前端注册动作：即便零件/整件数量均完成、只有模具缺口，也弹确认并提交{}签字，动作成功。
- 实际执行后端summarize/confirm_gaps/record_waiver/payload：带过期、对账和质量缺口的内部确认成功、签字字段真实返回、公式账仅读一次；无签字和无对象仍拒绝。
- 顾客需求draft→pending_confirmation→pending_review→approved真实状态函数测试，不依赖解析结果；冻结解析不调用客户需求写函数，另存工程证据。
- 页面成本上下文验证制造快照调用0次；会话请求永不返回时成本读取仍完成并渲染就绪。4.1–4.3状态读取3次共用一次请求快照；读取超时实际触发abort并返回cost-read-timeout，不返回空数据。
- 新口径只更新旧需求门禁测试4条矛盾断言；普通已审批需求不可直接修改、非包装解析前置与退回草稿护栏保留。旧数量测试mock返回值改为真实gaps字典，原数量断言未放宽。
- 最终22模块326项回归：325通过、1跳过；编译、成本JS语法、diff检查通过。没有验证部署后线上耗时，不能宣称线上45秒已经下降到某个数字。

## 范围

允许继续是内部签字，不伪造完整成本、不改计算金额、不删除缺口，不代签审批，不让质量签字绕过正式主数据/正式报价/发布校验。
旧签字不覆盖新增缺口；读写失败仍返回真实错误，不能以空对象或缓存旧数据伪报成功。
