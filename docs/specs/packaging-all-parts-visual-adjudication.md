# 包装 DWG 全件图形归属：CAD 候选 + 局部视觉复核（2026-09-24）

## 0. 现场与目标

当前 `resolve_business_parts()` 从 DWG 文字得出件名，却用名称插入点到连通分量包围盒中心的距离做全局一对一分配。它给出的是**最近几何候选**，不是整件轮廓或名称归属证明。酒盒“贴牌”的名称锚点 `ent:model:1433` 位于 `(3184.25,2538.77)`；当前分配 `region:DWG-P74`，中心距约 435.9 mm，包围盒 184.9×146 mm。权威资料的贴牌尺寸是 226×110.3 mm；资料只用于**离线对答案**，不得进入运行时模型输入、候选排序或规则。问题不限贴牌，整图所有业务件都应走相同的证据口径。

一次只读试验向现有 `qwen3.5-plus` 提供贴牌附近 10 个候选的 CAD 摘要、**不提供图像和权威尺寸**，模型返回 `choice=none, evidence_sufficient=false`。结论：LLM 可用于拒绝无证据绑定；只有坐标与尺寸摘要不足以提升识别率。需要局部 CAD 视图图像、图层语义和候选 ID，并用几何规则核验模型答复。

同一份当前本地代码的离线全件基线：酒盒推导 28 行，权威资料 28 行，但按**件名严格相同**只有 17 行；这 17 行中只有 7 行的长宽（允许互换）在两轴 ±2 mm 内。11 个权威件名缺失，另有派生名称填上总数。这个统计仅是验收参考，不证明那 7 行的图元归属也对，更不能为了把 7 变成 28 而读取金标参与运行。

## 1. 边界

1. 业务件来源仍仅是当前 DWG 的文字、实体、标注、图层和可由这些数据确定性渲染的图像。BOM、Excel、已审核快照、图纸 SHA 对应答案、价格和下游结果不得参与运行时识别，也不得进提示词。
2. 连通分量仅是候选几何片；**一个连通分量不等于一个业务件**，整件允许多个互不相连的线条组。不能使用“至少三个分量”“特定件名”“某张图的固定尺寸或坐标”之类样本规则。
3. 模型只判别“文字名称与哪组图元/哪块视图关联”及其依据，不产生 CAD 尺寸、材料、成本、工艺事实；不能凭模型信心把 `size_confirmed` 改成 `true`。
4. 本批不改报价、工艺、成本公式及 DWG 转换器；不改历史项目数据。所有修改先在本地验证，不自动部署。

## 2. 全件处理链

1. 继续解析 CAD IR。根据外切刀线、压痕、半穿、V 槽、参考线的图层/ACI/图例语义形成视图和结构候选；几何片可以聚成一个候选，也可保持多个相互竞争的候选。图框、标题栏、图例不作零件轮廓。
2. 每个非排除的件名锚点都获得候选集和排序证据（图框/视图归属、引线、包含或邻近关系、轮廓拓扑、重复/镜像关系、尺寸标注的空间关联）。距离只能是其中一个特征。候选不因最近就自动成为“已绑定”；同名重复、一个轮廓多个名称、候选距离相近或单一证据均为歧义。
3. 对整张图的**所有业务件**逐行评估归属质量；低风险也要有可解释的独立证据，高风险件进入模型复核队列。不能只处理贴牌或两个面纸。模型预算有上限时，未复核的高风险件仍标“待确认”，不能默认为原最近轮廓正确。
4. 模型看到的是 CAD 证据生成的局部栅格图（保留图层不同颜色、文字和候选轮廓编号）以及简短结构化候选表；超大整图缩略图不能作为唯一视觉证据。图像缺失/模糊/裁剪未覆盖文字或候选时，直接 `unavailable`，不可退化成“只凭文本猜归属”。复用全局模型设置和统一调用入口；不另存 API key。调用、失败、模型名、图像类型和候选数可审计，图像字节/原 DXF/思维链不入库。
5. 模型输出闭集：`selected_candidate_id` 必须是输入中已列出的候选 ID，或 `none`；附简短依据和 `insufficient_evidence`。服务端验证 ID、该候选的真实 CAD 图元、名称锚点/图像范围、独立尺寸标注定位。模型选了有效 ID 也只是弱证据；与 CAD 冲突或缺乏独立支持时仍是 `ambiguous`/`unbound`。模型不得新增图元、尺寸、件名或权威状态。
6. 模型拒答、超时、无 key、无合格局部图像、非法 JSON、越权 ID 时，保留确定性候选供人查看，并将不足证据的**归属状态**降为待确认；解析任务不报 500，也不把原错误绑定标“已识别”。
7. 仅空间关联到该候选/组图元的尺寸标注可确认为尺寸证据；全图出现同样两个数字不算确认。无独立证据时数值是 `bbox_only`，不进入成本/工艺门禁。UI 同时展示“候选图形/模型建议/人工已确认”的不同状态与证据，不把 `bound`、`derived` 或模型信心直接翻译成“识别正确”。

## 3. 可测调用契约

保持 `resolve_business_parts(project_id, cad_ir, geometry_parts, ...)` 默认纯确定性行为，增加关键字参数 `use_model=False`、`model_reviewer=None`（用于测试注入）。一键解析的业务件阶段在用户模型可用时启用 `use_model=True`；重建入口采用同一口径。模型审查调用方提供的请求至少含 `name`、`anchor_entity_id`、`candidates`（稳定 ID、图元 ID、bbox、图层/角色、距离、标注空间关系）和与本视图对应的栅格图；不含权威资料。`model_reviewer(request)` 返回 `{"selected_candidate_id": "<候选 ID>|none", "insufficient_evidence": bool, "reason": "..."}`。测试注入的返回也走生产同一校验器；额外键一律丢弃。

`match.bindings[]` / `authority_rows[]` / 业务部件文档逐件留痕：确定性候选、视觉复核状态、实际采用的 CAD region ID、是否人工确认、尺寸来源。每条 `binding.attribution` 至少包含 `status`（`verified_by_cad` / `review_needed` / `model_suggested` / `model_unavailable` / `human_confirmed`）、`reasons` 和可引用 CAD 证据；模型建议不能直接写为 `verified_by_cad`。要保持原有读接口可用，可加字段，不删旧字段；旧 `status` 的解读必须同步收紧，不能出现 `status=bound` 却没有任何可验证归属证据的矛盾。

## 4. 红测与验收

1. 真酒盒和真圆盘盒均从原 DXF 解析，所有非排除业务件都给出归属判据或逐件待确认原因；不允许只对固定名称分支。
2. 酒盒贴牌：模型明确 `none` 时，原 `DWG-P74` 必须被撤回到候选，不再是有效绑定；文档及 UI 不说“已识别”。同类远距离/歧义绑定在其它件也一致处理。
3. 模型选择不存在的 ID、伪造尺寸或 `size_confirmed=true`，服务端忽略越权内容，尺寸不改变，归属不升级。
4. 模型异常、无图像或没配置时，安全降级且不崩溃；对高风险件不能默默回到原距离绑定。
5. 同尺寸的左右件仍是两件；多个连通分量可构成一件，不能为凑资料件数增删图形；实体遍历顺序变化不改变结果。
6. 离线对答案按**整张图**统计件名、图元归属、尺寸误差、误绑定、拒答/待确认率，至少包括酒盒、圆盘盒和未参与阈值设计的留出图；不得只报告命中两件。误绑定率优先于自动覆盖率，没有留出图时不得宣称泛化达标。
7. 模型输入/输出日志中无 BOM/Excel 金标、图纸 SHA 查表答案和密钥；调用次数与失败可观测。相关既有测试不得因模型默认关闭而触发真实网络调用。

本 Spec 的红测只锁 API、全件复核、拒答/越权安全边界；图像质量与跨图纸准确率需要实现后再补真实留出集验收，不能用 mock 测试代替。

## 5. 本地实施与能力边界（2026-09-24）

- 已接入：一键解析/旧项目补推导使用统一模型设置，业务件解析可注入测试 reviewer；每件生成候选和归属状态，高风险件最多调用 8 次模型（环境变量 `PACKAGING_PART_MODEL_MAX_CALLS` 可调整，`PACKAGING_PART_MODEL_REVIEW=off` 可关闭调用）；其余件保留待确认而不是默认最近绑定。预览在内存由 CAD IR 图元生成 PNG，包含名称锚点、候选布局、局部彩色图层。
- 已接入：模型拒答、非法候选、超时和预算耗尽时撤销不可靠绑定；模型选中已有候选，也仅在名称落于轮廓附近且尺寸标注空间关联双重成立时提升为 CAD 证据绑定。界面可切换候选图形，并由有权限人员通过既有 PUT 接口人工确认归属；确认归属不确认尺寸，原 `size_quality` 保持。
- 本地真实视觉调用：`qwen3.5-plus` 对“贴牌”“左盖面纸”“底板”均未选出可信候选。贴牌最后一次调用给出明确原因：候选缺乏文字标签、引线或视图投影的直接关系。**这证明了安全拒答路径可用，不证明自动识别率提高。**当前酒盒在模型拒答的情况下仍需人工确认；不得把本阶段称作“28 件已自动识别正确”。
- 未完成的泛化验收：第三张独立留出 DWG、图元归属金标、复杂多分量整件候选与候选排序的准确率。部署前必须按 §4 第 6 条评估；仅两张现有图通过安全测试不等于可上线自动定案。
