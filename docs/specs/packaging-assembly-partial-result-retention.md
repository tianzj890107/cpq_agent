# 组装推荐逐条校验与空结果保护

2026-10-16。复现：两道模型工序中一条绑定未知零件，现实现丢掉全部工序，再按空接口降级，最终保存0道。

## 验收合同

- 模型原始连接、工序逐条校验。未知编码、连接冲突、单件制造工序、缺失字段等仅隔离该条，正确行继续保留；保留现有覆盖校验、制造去重和依赖重编号规则，不把无效绑定自动映射成另一个件。
- 接收模型结果的内部容器允许单行格式错误，最终落库仍是严格ProcessPlan。失败行以阶段、序号/编号、原因记录；不再因一行字段错误反复要求模型重新输出整份结果。业务层每次生成只调用一次组装模型（不改变底层传输重试策略）。显式组装按钮不再先重试材料/排模名称模型，原排模按钮和全流程准备入口保持原能力。
- 最新生成尝试独立保存状态、有效工序数、隔离原因和是否保留历史。部分结果明确部分完成；零道且多零件未解决不能报成功，也不编造总装；单零件无新增组装是正常结果。
- 新结果为0且旧工艺非空时，保留旧工艺内容、来源和绑定。输入未变的旧有效结果仍可使用，但本次尝试必须标部分完成；输入变更的旧结果只供查看，不改指纹、不自动确认，不得作当前成本依据。
- 模型超时、解析异常、行校验失败分别披露，不只显示“ValueError”。不显示敏感上游原文。无旧结果则显示具体原因与待补项。
- 工作区显示有效工序、最新尝试说明与逐条隔离原因；保留旧结果时不能把旧数量冒充本次新生成数量。刷新后说明仍可恢复。原有会话气泡先用户后Agent，样式和按钮不变，不新增人工确认门槛。
- 组装已保存但后续项目路线/BOM失败时，仍回显工序及路线未更新原因，不把成功生成的工序藏在失败任务后。失败/中断后前端只读刷新当前项目已存结果，原任务仍显示失败，不报成功。空的未解决结果不继续假装生成完整路线。
- 人工保存接口继续严格拒绝无效计划；不得放宽成本、方案隔离、权限和历史数据保护。只改本地，不提交/推送/部署。
