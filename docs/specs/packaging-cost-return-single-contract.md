# 包装成本统一回传契约

## 目标与边界

包装公式账是当前待回传成本唯一来源。成本回传、主数据写入、报告回传、报价基础成本使用同一份有效账，不改公式、费率、几何，不重算历史报价。非包装保留原算法。原报价和原销售任务落点沿用既有原子交接，不新建报价绕过失败。仅本地实现及隔离测试，不自动推送/部署或修改线上数据。

## 必须实现

1. 包装已有旧整机成本也必须重新投影当前有效包装账；旧投影在审计/历史保留，不将旧人工结果冒充新账。账缺失/过期不能借旧计划发送；数量采用账的报价批量。
2. 统一字段：`unit_cost`（元/只）、`quantity`、`order_total_cost`、`material_cost`、`processing_cost`、`other_cost`、`currency`、`cost_tax_included`、`cost_profile`、`cost_fingerprint`、`cost_result_version`、`gap_count`、`provisional`、项目与源报价身份。金额来自账；整单成本仅作单位成本×批量的明确投影；缺数据保留缺口，不默认零价。
3. 包装成本回传及已发布报告回传都带同一完整包装包和契约。相同总价但明细/规则版本变化，不能视为同一成本版本。主数据写入采用当前投影；历史写库记录不删除。
4. 旧任务兼容 `cost.total_cost`/`cost.total`/嵌套包装包，优先包装包；保留真实缺口和暂估状态。新包所有出口字段同源，不允许顶层成本与内嵌包互相矛盾。
5. 第2步快照包含产品行基础成本与数量，以及材料/加工/其他费用。包装成本不得当售价写入“价格”；更新基础成本不改销售毛利、加价或旧报价售价。
6. 打开/刷新原报价也能读到回传提示；销售确认后产品行和服务端快照都保存基础成本，恢复/重复确认不丢金额，不污染其他报价任务。
7. 报价身份只读查询使用工作流数据库连接/schema，不用主数据连接猜同名表；不通过自动新增数据库列来掩盖连接错误。

## 验收

隔离样本：材料2、加工6、组装人工0.3、包装1 → 单件9.3、1000只整单9300；整机旧结果99不得被回传。重算为另一版本后成本、主数据调用值、报告、报价快照逐段一致。补负例：缺账/过期、金额缺失、非包装旧行为、同价不同版本、异项目任务、刷新、重复确认、售价保留。保留旧已发布报价，不自动批量更新。

旧测试“包装已有人工成本99优先”与新唯一账规范冲突，应明确修订断言为新账优先且历史留存，不删除测试。真实线上PG和页面未执行的验证必须单独披露。
