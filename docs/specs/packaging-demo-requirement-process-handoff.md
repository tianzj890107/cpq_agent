# 包装演示：需求表、工艺确认、选人交接及报价展示

日期：2026-10-19。状态：已按用户明确授权完成本地实现及本地验证，未提交、推送或部署。

## 1. 范围与现状

本批只调整包装演示流程，不恢复已取消的排模/独立组装阶段，不改变成本公式、定价规则或其他行业流程。

已定位的现状：需求 PDF 仍实时生成且依赖非嵌入中文字库；包装检查仍有“需求名称/交期/商务与价格”，模型提示词还指定半导体旧表；确认及审核仍弹缺口二次确认；图纸页把工艺确认与发送合为一体，直接发角色池并跳成本；报价正文及 Word 各自添加演示字样，Word 还重复输出客户抬头。

## 3. 检查表统一八行

包装规则检查、AI 输入、AI 输出映射、确认页、历史检查展示统一下列顺序：

1. 一.项目名称
2. 二.需求
3. 三.产品技术规格
4. 3.1 产品与订单
5. 3.2 成品尺寸与盒型
6. 3.3 材料
7. 3.4 印刷与表面工艺
8. 3.5 包装与物流

项目名称取已保存的项目名称，兼容需求标题；需求取需求正文及报价承接的需求文本；技术规格及五个子分区沿用现有字段事实。父项是汇总，不重复扩充成更多检查行。不要求先解析图纸，不把尚未上传的图纸作为需求确认阻断条件。

删除包装确认检查中的独立交期、客户信用、商务与价格等额外检查行，但不删除底层字段。零/否是有效值；空值不能伪称齐全。模型少项、错项、返回旧行业项时，按当前八行目录回填并保留真实待补充状态，不能按位置错配。已保存旧检查只做展示投影，不触发模型、不改历史。

## 4. 包装非必要缺口不弹二次确认

- 点“确认及审核”直接提交，成功进入图纸解析。空白尺寸、克重、样品交期等非必要完整性缺口保留为非阻断状态，不弹“还有N项/带缺口继续”，不要求签字理由。
- 创建/提交、旧审核兼容入口也检查同类弹窗；包装演示同一操作不重复问询。不得伪造人为签字或宣称缺字段已补齐。
- 保留登录/权限、项目不存在、读取/保存失败、缺少真实图纸或没有可用工艺等确实无法执行的错误；不吞掉失败冒充成功。删除/驳回等有损操作的确认不在本批取消范围。非包装保留既有行为。

## 5. 独立确认工艺，再选人发送

### 5.1 确认

- 全部零件当前版本工艺推荐完成后显示“确认工艺”，按钮沿用既有样式。点击只确认、不创建交接任务、不调用成本、不跳页。
- 确认必须服务端持久化，包含操作者、时间及当前业务零件/有效工艺内容版本。不可复用被取消的独立组装确认冒充零件工艺确认。
- 刷新仍恢复确认；改候选、组成、尺寸、材料、用量或重生成有效工艺后，实际输入/工艺版本发生变化即失效，重新显示确认按钮并隐藏发送。单纯读取、重排展示、失败重试未改变有效工艺时不失效。
- 重复确认同一版不重复写审批记录。未完成/部分失败不可确认，非工艺工程师或既有允许的管理角色不得确认。

### 5.2 发送

- 仅当前版已确认后展示“发送至报价人员”；点击打开沿用现有风格的人员选择窗，不直接发送角色池，也不顺带确认。
- 使用现有人员目录，默认筛选报价人员；支持姓名搜索，保存真实人员标识。列表慢/失败显示重试；无可选人员明确说明，不暗中改成角色池。
- 取消、关闭及未选人不发送。选人并点击发送时才 POST，携带 `target_type=user` 与真实 `target_user_id`；沿用任务授权、参与权、原报价关联及防重复能力。
- 成功/失败均停留原图纸/工艺页面，保留选中零件、滚动及图纸，成功只显示既有消息气泡与状态。失败可重试，不假报成功。
- 服务端所有发送路径（HTTP、Agent、兼容草稿）都验证当前版工艺已确认，不能靠隐藏按钮防绕过。未确认或已过期时，不生成路线副作用、不创建任务；返回“请先确认当前工艺”。缺字段等非必要缺口不能升级为新的人工确认门槛。

## 6. 报价及 Word 清理

- 包装结果预览与 Word 不显示“演示报价单，不得用于正式交易”及其标点变体。不是把它替换成其他同义免责声明。
- Word 删除标题之后重复添加的独立“客户：茅台”段；客户仍可在商务基本信息表中正常出现，不能全局清空客户。不得写死客户名，只对包装商务导出移除重复抬头，其他行业保持原样。
- 保留产品规格、型号、数量、单价、总价、税率税额、商务条款；读已保存金额、不重新定价。内部 `demo_only/draft`、来源、正式发布保护和历史记录不因去文案而删除，也不宣称正式交易能力。
