# 包装全流程实测缺口（2026-09-28）

## 0. 实测基线

修复前的本地隔离服务上，酒盒 DWG 跑完 8 个图纸步骤，生成 28 个业务部件，但几何绑定 0 件；圆盘盒跑完同样 8 步，生成 65 个候选，混入图例、装柜说明、尺寸说明，绑定同样为 0。酒盒 BOM 47 行，6 种材料未映射；成本有 65 条缺口，正式报价被阻断。带缺口草稿回传的任务可领取，但第 2 步卡片快照缺少包装整包。两条快速报价案例只能保存试算，不能当正式报价。

## 1. 必须修复的跨系统合同

1. 一体化服务的 `/agents/quote/*` PUT 必须同 POST 一样完成鉴权与转发。前端修改快速报价工作区的请求必须返回业务结果，不得 404。
2. 回传快照不得静默截断。至少支持本轮约 269 KB 的包装包；超过合理上限则整个业务动作显式失败并回滚，不得标记步骤完成、发任务或只记录 `snapshot_sections`。派单前必须在同一事务读回本次各段的**内容**，不能只看键是否存在（旧包有同名键也可能掩盖失败）。重开卡片时，`s2_packaging`、`s2_packaging_cost`、`packaging_package` 与既有 `quick_quote_price` 并存。
3. 报价来源已确认的包装字段应携带可追溯来源与确认态；仅有值、不具备来源的字段不可被自动升级。图纸语义重跑不得覆盖人工确认。
4. 业务部件候选必须排除图例、标题栏、装柜说明、数量/尺寸孤句。过滤只能依据通用语义与图纸结构，不能按样本文件名、哈希或客户答案表判断。不能确认边界或尺寸的部件继续标为待确认，绝不把包围盒当已确认展开尺寸。
5. BOM、工艺、成本必须保留逐项缺口：材料原文无法映射、无权威价格、缺用量、缺工时、缺公式等不能用默认价/默认量填平；成本总额只是部分成本时，页面与回传包都必须显著标示“非完整成本”，正式发布继续阻断。
6. 快速报价的未审核演示费率只能用于试算；正式保存继续拒绝。金额读写与展示使用确定的小数精度，不得出现 `37.809999999999995`。旧进程运行旧代码属于部署检查项，健康检查应能读出构建版本或启动时间，便于发现未重启。
7. 快速报价状态每次变化都必须持久化，而不是只在仓储对象的内存字典上原地修改。重启后需求、匹配、基准、工作区、差异、报价、版本、行业和模式必须逐字段恢复；确认后的卡片摘要也要落盘。任何读取不应把已有业务实例静默重置成空壳。
8. 快速报价案例准入既然允许缺少数量档位，后续“选基准”就必须可用：无档位时采用该已审核案例的 `standard_price`，在基准快照标明价格来源为标准单价、未命中档位；有档位则沿用档位价。数量变化若没有已审核差额规则仍按原门禁提示，不得凭空推算阶梯价。不能出现候选列表显示“可用”、点选却报“缺数量档位”的前后矛盾。
9. 全仓测试必须隔离进程级配置：GET 冒烟和文件预览探针不得继承其他测试残留的 `CPQ_SSO`、登录服务地址或已导入的 App 单例，避免健康接口被假环境误报 503。真实服务的 503 仍须保留红灯，不得靠跳过断言放行。

## 2. 验收

- 隔离端口跑酒盒与圆盘盒 DWG，两者不得把明显非零件文字列成业务部件；全部字段均须披露来源与确认态。
- 酒盒按销售→工艺→成本→销售跑到带缺口草稿任务，领取后第 2 步快照可读回整包、缺口及留痕；重放不重复派单。
- 未补权威材料价/费率之前，正式报价不得成功；把草稿误标为正式为失败。
- 原有行业、权限门禁与全仓测试继续通过。测试数据使用隔离目录或显式测试标识，不清理用户数据。

## 3. 仍需业务证据的边界

- 酒盒 28 个**业务部件候选**不等于 28 个已确认 CAD 轮廓；本轮真样本几何绑定仍为 0。模型建议和包围盒不能冒充图纸展开尺寸。要让所有件用于自动工艺，需要人工在图上确认轮廓/尺寸，或提供可审计的权威 CAD 标注与零件对应关系。
- 酒盒材料原文仍有 6 种未映射，成本价、用量和部分标准工时仍缺权威值。本轮只保证缺口可见、草稿可回传、正式发布受阻；不能把 mock 数据或演示差额率提升为正式价格。
- 旧进程重启前只存在内存、从未写盘的快速报价状态不能被重建；修复保证新操作持久化，已有报价版本仍可从卡片快照单独读取。
