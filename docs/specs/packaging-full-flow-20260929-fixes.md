# 包装全流程衔接修复（2026-09-29）

## 实测事实与边界

酒盒 DWG 的图纸流程 8 步完成，但报价原文中的盒型编码、内尺寸、闭合方式、面纸克重等仍未进入需求字段。快速报价的 CAD 材料注记含 235g，而销售需求写 225g；这是冲突，不可擅自改成某个“正确值”。业务部件清单是 28 件候选，几何区域 263 个；没有证据的尺寸和材料价格不得按答案表补齐。FI1 可读包装成本却在回传报价时被项目级 ACL 先行拒绝。

## 合同

1. 包装报价原文中的**显式标注**可在保存需求草稿时确定性填入空字段：盒型编码、盒族、闭合方式、`内尺寸 L×W×H mm`、`面纸 N g`、内托类型、V 槽、报价数量。只接受完整、无歧义的标签和值；未标注或多个不同值不猜。字段来源标 `user_text`，留下报价文本证据；不能覆盖已有人工值、CAD 确认值或已有来源。未被人工确认的销售文字仍是待核字段，不可伪装成 CAD 确认。
2. 技术侧包装盒型控件必须能够显示和保存知识库里的真实盒型编码（如 `YT-DWG-WINE-700ML`）及真实闭合方式文字。已有值不在固定枚举时不能显示为空、保存成空；新建时仍允许现有通用枚举。
3. FI1 对**已有成本、本人可读、未归档的包装项目**可执行 `POST /requirement/packaging-quote/send`；项目 ACL 仅降为 contribute，接口原有角色门禁、成本缺口门禁与放行原因门禁照旧。其它财务写路由不得随之放宽；无读权项目仍 404。
4. 快速报价 CAD 注记与销售手填值冲突时，必须显示冲突与两边的数值；没有销售输入时 235g 可作为“图纸解析值”呈现，但不能称其为销售确认值。DWG 不提供的内尺寸继续缺失，不使用图纸幅面替代。
5. 业务部件的几何绑定、材料价格、用量、工时缺失时继续披露缺口。部分成本可用于明确标记的草稿演示，但正式报价继续拒绝。不得写入伪造权威价、按 28 件金标硬凑几何、或让模型输出结论性尺寸。

## 验收

- 纯函数测试覆盖显式文本、歧义文本、人工值保护；保存与重载后字段和来源一致。
- ACL 测试覆盖 FI1 已有成本回传、FI1 其它写路由、不可见项目与原有角色门禁。
- 包装表单测试覆盖真实盒型编码及闭合方式回显后保存不丢值。
- 酒盒和圆盘盒解析、快速报价草稿、BOM/路线/成本、带缺口回传的原有回归继续通过；正式发布仍被成本缺口拦截。
