# 成本回传版本与会话同步修复

## 范围

修复 2026-10-15 两份 DWG 线上验收的共同阻断点。仅本地实现、测试；不部署、不执行线上迁移、不修改已有业务数据、公式或 CAD 规则。

## 验收要求

1. `cpq_wf_handoff.source_result_version` 使用 TEXT，生产建表入口同时提供旧 varchar(64) 列的幂等扩容。保留完整成本版本和 fingerprint，不截断、不清空；旧行、唯一键与回传事务不变。同版本重试复用交接，不同 fingerprint 不串版。
2. 成本页嵌入工作台时，按钮触发的用户消息、过程、结果、失败必须通过既有看板桥显示在父壳。一轮一个执行卡，先用户后助手；不能仅写入隐藏 iframe 的旧线程。保留独立页显示，不新增业务 API。
3. 同一任务的已完成、部分完成、失败、阻断、中断状态不能被迟到的 queued/running 覆盖。前端实时、时间线合并和后端持久化规则一致；就地更新保留首次时间戳和序号，不能把卡片移动到用户消息之后。真正重试使用新 run/task ID。
4. 图纸页部分失败上报 task-partial，不可借 task-completed 强制显示成功；全部工艺失败为 failed，而非已完成。
5. 确认成本同样先发用户消息。成本卡明细与错误原文保留，父壳负责统一持久化，嵌入页不重复写旧 session-note；不修改成本计算、权限、销售收件人或报价进度。

## 验证边界

专项红测须先实际失败再修复；包含生产 DDL、完整长版本交接/幂等、前后端终态乱序、真实 DOM 成本卡桥事件与失败信息。真实 PG 迁移及线上双卡片继续至最终报价，需后续部署授权；本轮不得声称完成这些线上检查。

## 本地验证记录

- 实现前专项 6 项：5 项实际失败（DDL、前后端终态、部分失败转发、隐藏成本线程）；完整长版本受控事务交接已通过，作为保护项保留。
- 实现后扩展为 9 项，追加两次回传不同指纹、首次时间戳/序号、慢用户消息顺序、全失败批量、真实成本回传/确认失败按钮链路、桥断开收尾及独立线程回退。
- PostgreSQL 本轮只检查生产 DDL 及受控事务引擎的完整版本保存/幂等；没有运行真实 PostgreSQL 迁移，不将假库等同于真实数据库验证。
