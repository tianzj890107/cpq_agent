# 包装损耗：父件/组成关联与材料别名修复

## 1. 范围

修复整件工序漏读组成材料损耗、件名“忖纸”未复用既有“衬纸”别名规则。
不新增费率、不写线上库、不改公式、校版分摊、包材内置损耗、报价放行门禁。
本次用户明确要求完成实现，包含业务实现与隔离回归测试。

## 2. 验收口径

- 需求显式损耗（包括 0）优先；否则只读取包装/通用行业、有效期内、
  `factor_type=scrap` 且 `applicable_scope=process_formula:<当前公式编码>` 的工序因子。
  工序因子值是本引擎现有的金额上浮比例，不是良率或投入废品率；不自动转换后两者。
  同级取最新生效记录；不得借用其他行业、其他公式或无作用域因子。登记值 0 有效。
- 没有工序专用因子时，延续既有材料继承口径：
  指定组成只继承该组成；整件继承该件全部材料。归属读取 BOM 的
  `size_source_json.parent_part_code/section_id`，兼容 `<父件>::<组成>` 编号。
  只在全部相关材料都有值且一致时继承。混合材料不同损耗或部分未知时保留 None，
  不平均、不取最大、不跨件、也不借工序名称中的“纸”掩盖冲突。
- 材料损耗继承与工序因子二选一，不相加、不连乘；整单组装人工继续不叠加材料损耗。
- 工序明细保存损耗来源、依据材料编号，详情中文可读；缺口标明零件/组成，方便定位。
  同时修复明细序列化把 `amount_with_loss` 固定存为 0 的问题，逐行损耗后金额与汇总同口径。
  同名工序的缺口按零件及路线步骤引用定位，不再全部取第一条同名工序金额；
  指定引用找不到就披露影响金额未知，不串到其他零件。
- 件名推定复用现有别名规则，不加入酒盒/BP09 特例；明确材料原文始终优先。
  历史演示输入为“未识别材料（估算）”且无材料编码时，重算可按件名补推定，
  必须披露推定来源、保留原始文字及已保存 mock 参数，不改确认材料/历史文档。
- 新计算记录损耗解析版本。旧计算保留历史金额，仅标记待重算，不读取时偷偷重算。
- 未知材料/工序仍保留金额并记 advisory，不为了清除提示填默认率。

## 3. 回归

`tests.test_packaging_loss_parent_section_red`：隔离 SQLite/JSON 与知识库快照，
实际执行整单 compute/save/load；覆盖随机父件编号、两组成同率、混合率、部分未知、
前缀相似件不串用、显式零、组成定位、专用因子作用域/有效期、旧成本标记、中文追溯。
同时回归原损耗来源、材料相似度、排模分摊、成本明细口径与整件费用分组。

## 4. 实测结果

实现前专项实际失败：7项断言失败、1项来源字段缺失（另3项已有保护通过）；
补充同名工序金额定位红测亦复现不同零件错误引用第一行金额。
最终18模块298项，297通过、1跳过；JS/Python语法及diff检查通过。
只在隔离 SQLite/JSON 与知识库快照执行计算/保存/回读，不连接线上库写数据，
不以提示数归零代替金额核对；未部署，不宣称线上酒盒已重算。
