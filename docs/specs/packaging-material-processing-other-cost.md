# 包装成本：材料、加工、其他费用

整单、汇总、底部成本栏统一材料/加工/其他费用三项，合计仍来自同一公式账。加工费单列；其他费用展开仅组装人工、包装费及其它项目费用，不显示模具摊销/运输费。

新测算政策：不计模具摊销/运输费，不查询这两类知识库或产生对应缺口。独立制造人工归回所属零件加工；已含人工的加工公式不额外加人工。组装人工仅scope=project的新增组装工序，按标准秒数×小时费率÷3600计费，用量1，不乘关联零件个数，不重复制造工序。禁止硬压到某个金额；30秒×36元/小时=0.30元，一至三道对应0.30–0.90元仅是估算示例。

新政策版本存source_versions.expense_policy。旧账原金额/明细保留，政策不一致标待重算；不得将历史制造人工直接改名组装人工，或仅隐藏旧费用而让它继续成为当前有效成本。历史保留差额明确标旧口径，不做线上重算或数据迁移。

原始labor类别可保留在明细（说明制造人工的计费公式），但新账labor_total仅组装人工，process_total包含制造人工；读投影与加工明细合计对齐。旧计算函数仍可单独验算模具/运输，不用于本次新项目账。

## 红测与验证

专项测试：`tests.test_packaging_material_processing_other_cost_red`。实现前实际失败点：成本仍查询工装规则；制造人工未进入零件加工；缺少组装人工专用汇总；前端加工仍在其他费用；旧政策未失效。真实引擎新增测试还复现了未知名称的最终组装缺失费率、人工总额为0，而非应有0.30元。

专项覆盖取消费用不查库不计费、制造与组装归属、跨零件用量不重复乘算、真实临时数据库写入/回读对账、前端三项分类及汇总金额、旧账不改金额而标过期。旧回归中“必须显示模具/运输”和“必须产生模具缺口”两条断言按新需求更新，印刷与包材缺口、独立模具/运输公式验算继续保留。

所有写入验证在隔离临时库；不重算线上历史项目、不修改知识库费率。组装金额由已有工时和费率确定，不保证任意复杂产品都低于某个硬上限。
