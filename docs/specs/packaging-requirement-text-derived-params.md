# 包装需求原文 → 成品参数（包装产品名称 / 包装品类）

状态：Spec + 红测（待实现）
范围：1.1 需求原文抽取 + 4.x 回传销售的参数族投影
相关：`docs/specs/packaging-cost-to-quote-integration-projection.md`（§2.5 / §2.6）、
`docs/specs/packaging-requirement-template.md`（3.1 产品与订单）

## 1. 现场缺口（34 线上实测，项目 `6beeeebb19a1`）

包装需求单 3.1 的前两项是必填：

- `packaging_product_name` 包装产品名称
- `packaging_category` 包装品类

这两个值只写在**报价原文**里（需求单 `description`）：

> …700ML双开门酒盒；**包装品类酒盒**；盒型编码YT-DWG-WINE-700ML…

但 1.1 的报文字段抽取（`requirement_service.extract_explicit_packaging_quote_fields`）
只认了盒型编码 / 盒族 / 闭合方式 / 成品内尺寸 / 面纸克重 / 内托 / V 槽 / 数量，
**没有认这两个键**。于是：

- 需求单 `data` 里始终没有这两个值；
- 4.x 回传销售按包装族校验必填，被拒：
  「报价必填的成品参数还缺：包装产品名称、包装品类。请先在「参数推荐」环节补填并确认」；
- 一次已经算齐的包装成本（材料 11.46 / 合计 15.60 元、账已对平、`cost-review/confirm`
  零缺口）**卡在回传这一步**，报价侧收不到技术结果。

这不是缺数据，是**原文里明明有、抽取器没认**。

## 2. 规则（通用，不针对任何一张图纸）

抽取只做两件事：**抄录带标签的值**、**按通用词表认品类**。所有规则与具体产品、
具体 DWG、具体客户无关。

- **C1 标签抄录**：原文出现「包装产品名称 / 包装品类」标签（后面 `:`、`：` 可有可无，
  值为到 `；;，,` 或换行为止的片段）时**逐字**抄录。
- **C2 品类词表**：没有标签时，用**通用包装品类词表**（酒盒 / 圆盘盒 / 礼盒 /
  礼品盒 / 食品盒 / 保健品盒 / 化妆品盒 / 药盒 / 烟盒 / 玩具盒 / 服装盒 /
  日用品盒 / 茶叶盒 / 月饼盒 / 电子盒 / 纸盒 / 木盒 / 展示盒 / 手提盒 /
  折叠盒 / 精装盒 / 包装盒）按**最长命中**判定品类。命中多个不同长度时取最长；
  同一长度命中多个不同词时**不判**（有歧义不如留缺）。
- **C3 产品名称**：没有标签时，取**同时命中品类词**的文字片段（片段按
  `；`、`;`、`。`、换行切分），并**排除**本身就是「包装品类X」标签的那一片段。
  仍取不到就留缺 —— 不编。
- **C4 只填空位**：任何人已填的值（人工、CAD、模型）及其来源**一个字都不改**；
  抽取结果来源标 `user_text`，证据原文存 `quote_text_field_evidence`，
  溯源进 `field_provenance`。
- **C5 历史项目按同一份抽取补投影**：4.x 回传时，需求单 `data` 里有值的字段照旧投影；
  `data` 里没有、但**同一份原文抽取**认得出的字段，投影时补上并注明来源是
  「需求原文抽取」。历史项目不需要重建需求单。**只在真的补了东西（补了行，或这份参数结果
  还没有产品族）时落盘** —— 回传可能被重复触发，每次写一版计划只会往历史里灌噪声。
- **C6 认不出仍然如实点名**：抽取补完还缺的必填，回传照旧逐个点名拒绝，**不编值**、
  不豁免、不静默放过。

## 3. 验收标准

1. 纯函数 `extract_explicit_packaging_quote_fields(text)`：
   - 「包装品类酒盒」→ `packaging_category == "酒盒"`；
   - 「包装产品名称：700ML双开门酒盒；包装品类：酒盒」→ 两键逐字；
   - 无标签但文字含「酒盒」→ `packaging_category` 由词表命中，`packaging_product_name`
     取含品类词的片段；
   - 与包装无关的文字 → 两键都不产出；
   - 同一文本出现两种不同品类词（如「酒盒」与「礼盒」同长度）→ 品类留缺。
2. `merge_explicit_packaging_quote_fields`：已有值（含 `field_sources != user_text`）
   不被覆盖；空位才填。
3. `cost_flow` 的包装参数投影：需求单 `data` 里没有这两个键、但原文认得出时，
   回传前投影补齐；`data` 里已有值时原样保留。
4. `ensure_packaging_params`：连续两次调用（第二次没有任何新增）只落盘一次。
5. 回归：`test_packaging_cost_to_quote_integration_projection_red`（含 b1–b3）、
   `test_packaging_round_geometry_and_requirement_facts_red`、
   `test_packaging_full_flow_20260929_red` 不回退。

## 4. 明确不做

- 不从 DWG 幅面、BOM、案例反推这两个字段；
- 不引入新的产品族或需求字段键；
- 不改成本公式、费率、门禁判据；
- 不在这两个字段上做任何「按项目名 / 客户名特判」的分支。
