# 包装圆形、多片段部件与全流程事实一致性

日期：2026-10-08。范围：本地实现与自动化验收，不授权部署或修改线上项目。

## 1. 图纸解析

- 完整圆、跨零度圆弧、椭圆、带 bulge 的折线必须保留曲线形状；不得以端点弦代替圆弧。曲线采样必须有误差与点数上限。
- 连通分量只是候选，不等于业务件。一个件可包含多个独立闭合或开口图形；组成片段、孔、排模副本、参考线必须分别表达，不无条件并集。
- 名称、材料、标注、块路径、图层与排版空间证据共同参与归属。模型仅从真实候选中建议，不得造图元或尺寸；失败可降级且披露，不按酒盒/圆盘盒答案凑数量。
- 多片段件只有所有声明组成均有证据时才称完整；默认最高分归属不等于确认尺寸。已有人工绑定不覆盖。仅包围盒的尺寸不得放行正式单件工艺/成本。
- 合成回归须包含独立圆、双半圆、跨零度弧、椭圆、带 bulge 折线、孔与排模副本、不同大小/平移的多组成件。

## 2. 零件行显示

- 尺寸统一为 `307.07 × 528.89 mm`，严格保留两位小数。
- 优先人工确认尺寸，其次图纸尺寸，最后已绑定 CAD 的估算尺寸。未知轴显示 `—`，禁止显示 0 或从成品内尺寸冒充零件展开尺寸。
- 零件行不再展示“仅几何包围估算，尺寸待确认”“系统按最高分 CAD 候选自动确认归属；尺寸仍须核对图纸标注”“证据待确认”。证据与门禁数据保留，详情仍能核对，隐藏文字不代表取消校验。

## 3. 已知需求继承

- 读取 RequirementDoc.data，兼容旧顶层数据。包装产品名、数量、内长宽高、克重、盒型、闭合方式来自已保存需求，不被模型改写。
- 参数推荐和智能补全共享确定性事实映射；已知值标来源“需求单”，不标经验推荐。缺失值不得因模型猜测自动成为确认事实。
- 原文“225g面纸”“面纸225g”“双开门/对开”应等价抽取。

## 4. 金额与业务门禁

- 定价面板、第五步明细、第六步正文及导出共用已保存报价结果；未税总额、税金、含税总额分别命名，不将单价两位显示值重新乘数量。
- 草稿明确不可正式导出/完成；保留成本缺口、审批和发布门禁，不修改 draft 为 approved 绕行。

## 5. 报告 15 项交付矩阵

以 `docs/reports/online-packaging-e2e-20261008.md` 的编号为唯一索引，各项须独立可验收：

1. 同精度同税口径金额；2. 确定性需求继承与建议隔离；3. 完整零件/可靠尺寸；
4. 能力查询带鉴权，失败为未知不误登出；5. 包装需求同义表达；
6. 带缺口内部草稿财务交接与同项目待办；7. 整单/单件成本与批量/用量分开；
8. 包装报告事实汇总、结论输入和正式审批；9. 销售项目名与真实会话轮次；
10. 项目列表/历史请求超时重试，不伪报空库；11. CAD 不以前置金标为条件；
12. 完整片段预览与控件布局；13. 成本阶段文案纠正；14. 草稿 Agent 结论；
15. 包装匹配用语、JSON 隐藏与消息历史。

每项必须记录已实现/未实现及实际执行的测试；不得以部分测试通过宣称整个矩阵完成。真实两方案正确性还需独立 DWG 复验，不能用合成测试替代。

### 6.1 红测和回归

- 新增 8 个测试模块，共 29 项行为测试。分别实际运行并观察对应实现前失败，再完成实现。后补的圆形预览、残缺 JSON、矛盾克重、批量确认缺口也单独复现了失败。
- 代表性红测：圆弧只有弦线；椭圆被跳过/半椭圆错误闭合；多轮廓复合件无候选；圆径向标注无有效尺寸；需求 220.5 被模型 260 覆盖；第五步精度丢失；内部草稿无合法交接入口；首页无限等待；草稿结论为空；批量不符却无确认缺口。
- 最终组合回归：20 个相关测试模块，**300 项通过**。覆盖新模块、原有轮廓/连通链、下游、视觉判定、报价闭环、草稿可见性、精度门禁、财务交接、业务件 BOM 与 CAD 预览。
- 修改旧自动补全契约测试：只将自动调用改为 `knownOnly: true`，防止模型猜测自动保存；保留原有参数/自动填充流程断言。不是删除门禁或跳过失败测试。
- 已通过修改 JS/HTML 内联脚本语法检查及 `git diff --check`。未启动本地服务、未执行浏览器端到端测试、未访问/修改线上数据、未提交/推送/部署。
