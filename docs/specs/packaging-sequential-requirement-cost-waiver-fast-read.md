# 包装需求顺序、成本签字放行与轻量读取

2026-10-13，用户授权本地实现；不部署、不改线上项目。

- 1.1提交、1.2确认、1.3审核客户需求不依赖2.1图纸解析。缺图/未解析只在2.1及下游实际消费解析结果时提示；既有审批角色和状态转换不放宽。
- 2.1允许解析已提交/审核的包装需求。冻结客户需求不直接改写；解析字段另存工程证据，保留IR版本及原需求状态/版本。草稿仍走原字段写入；客户需求修改仍走修订，不靠退回草稿才能解析。
- 4.1前后端共用实际缺口。财务明确点击“仍要继续”提交waiver（含空对象）后，工装摊销/缺价/零元/成本过期/对账问题可按内部暂估签字确认；缺口、旧版本和金额不消失，不冒充正式成本。角色、无确认对象、写入失败仍不得伪报成功。
- 签字覆盖同一缺口复用，不反复索要；输入变化或新增缺口仍披露。签字确认是内部确认，不自动放宽正式发布/主数据写入/外部正式报价校验。
- 页面成本读取只取业务清单与现有公式账，不加载完整制造快照、BOM/路线渲染或逐件图纸预览。确认链路同一份成本视图复用，不重复读/建多个大文档。纯GET不触发模型或成本重算。
- 前端不把接口错误误判空清单；显示真实缺口/内部暂估状态，沿现有控件和工具卡风格。

红测包括无解析完成1.1–1.3、审核后解析不改客户字段、实际前端缺口签字请求、空waiver有效、质量异常签字仍成功并留痕、无对象与权限护栏、读取/确认重负载调用次数。

工程输入只读投影仅采用与当前需求修订版及IR锚点一致的confirmed字段，且只填下游缺值；不得覆盖已有客户尺寸或把模型弱候选升格。
内部签字确认同步至4.1–4.3状态投影，可继续提交工艺经理；正式发布、对外正式报价和主数据写入保持原校验。
会话回放放后台，不阻塞已有成本展示或把回放慢当成成本读取失败。
4.1–4.3状态投影在每次请求内复用成本快照（不跨请求缓存）；成本GET20秒可取消超时，明确提示可重试，不误判成没有成本/空清单。初始读取失败提供原风格重试按钮。
