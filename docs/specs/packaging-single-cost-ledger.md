# 包装统一成本账：单件是整单明细的视图

## 目标与边界

包装仅由 packaging_cost.compute_project/build_cost 的公式引擎生成成本事实。4.1、4.2、汇总、单件详情及报价读取同一 estimate_id、场景、数量和来源版本。不得通过同步两个独立金额解决一致性，不把历史单件材料记录作为正式成本。

## 分类与数量

- 主展示材料、人工；其他费用保留加工、模具摊销、包装、运输、其他的展开明细，禁止统称制造费用或并入人工。
- 单件行按整单明细 part_code 归集，已含每套用量及损耗；行小计直接来自明细，展示单件价才除以每套用量，不再重复乘用量。
- 项目总成本 = 所有零件归集小计 + 未归属零件的项目费用。加工不得既在零件里又在项目里加一次；损耗只加一次。
- 明细归集与各类别、整单总额对账。失配、非法/缺金额须披露并禁止确认，不允许用残差伪造人工或材料。

## 读写与状态

- 4.1 和单件详情不读历史 packaging_part_cost 来判断有效性；当前整单未算=待测算，整单 stale=待重算，已有有效明细=显示金额。
- 单件重算更新同一整单账（当前实现可全单重算以保证最低开机费、批量与项目费用一致），任务结果返回所选件视图；不得自行把传入零件用量改成报价批量。
- 包装一键测算和重试只提交一次整单计算，不先逐件重复运行再算整单。不更改其他行业旧逻辑。
- 数量输入保存到同一需求源；保存失败不提交计算。报价数量变化采用同一个漂移判定，单件、整单与下游统一待重算。新一轮整账重建后撤销旧财务确认标记，保留历史正文和操作记录，不把上次确认套到新金额。
- 保留历史记录，不迁移/删除、不伪造价格，不扩大费率默认值、审批或线上操作权限。

## 验收

纯数据测试覆盖同账归集、损耗与用量、项目费用不重复、过期/未测算、明细失配、单件与项目入口共用build_cost；前端测试覆盖分类名称及包装批量只调用一次。红测须实现前实际失败。

## 实现及测试记录（2026-10-10）

- 实现前5项测试失败（新归集服务缺失、旧读写及前端未接入）；数量漂移、重建撤销旧确认的追加红测也各实际失败后修复。
- 新增 packaging_cost_ledger：只读整单公式结果，归集每件材料/人工/加工及项目级费用，保留计算批量与来源版本，不读写旧单件成本作为有效账。
- 替换业务件成本POST/GET和4.1读侧；几何兼容入口只有唯一业务归属才可转统一账，重叠时不给任意件记账。成本写权限对包装统一按 COST_WRITE_ROLES。
- 包装前端测算/重试一次提交整单，不自动切当前页签；材料、人工主展示，其他真实费用用现有details与按钮样式展开。公式账单件只读，不允许绕开公式直接保存另一份单件金额。
- 旧测试中要求“单件独立落库”的路由断言按本Spec更新，尺寸/材料纯函数、非包装逻辑与黄金公式测试保留。旧前端路由计数基线9更新为现有版本11。
- 回归包含真实临时SQLite中 build_cost → 保存 → load_cost → 单件归集与整单对账，不访问线上库。覆盖损耗一次、用量一次、报价批量变化、未算/过期、未知归属、非法金额、项目费用缺金额、总额失配、旧确认撤销、数量需求源更新；Node运行真实前端批量函数与分类渲染函数。
- 相关回归243项通过，3份JS语法与diff检查通过。没有线上部署、数据重算、浏览器视觉验收或Git远程推送。
