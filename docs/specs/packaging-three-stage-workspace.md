# 包装3.1–3.3业务工作区

状态：Spec + 红测（已实现）；本地验证，未提交推送部署。
红测：`tests/test_packaging_three_stage_workspace_red.py`

## 页面与数据合同

- 3.1方案与部件：当前图纸方案、原图入口、图纸顺序零件编号/名称/材料/尺寸/每套用量、多组成明细、候选切换入口及真实缺项。多方案选择走既有scheme接口，保留未选方案。无整合图上传要求、整机概览、连接关系、成本统计。
- 3.2排版排模：当前方案排模及原图入口、关联多个零件/组成、纸张/板材尺寸、开料长宽、每版数量、模数及来源、分摊方式。方向/边距/间距仅有依据才显示；利用率必须有可算面积与数量且在0–1内。无排模零件/组成列展开尺寸、余量、最终开料尺寸，余量可修改并实际进入同一成本引擎。不得把排模草稿静默升级；配置修改使既有成本过期。
- 3.3工艺路线：每个完整业务零件一套工序与来源、设备、适用要求、计费参数、真实或披露估算工时；多组成只提供上下文，不独立编制工艺（见 `packaging-whole-part-process-unit.md`）。必要后道与组装单列，不凭名称把所有逐件粘合误判为项目组装。项目级包装路线必须绑定生成时的方案；当前切换到其他方案时不得显示为已采用，旧多方案路线若没有可验证的方案归属也显示待更新。页首仅数量/缺口/路线状态。不展示成本金额、整机参数、机械装配模板。
- 数据仍来自现有业务部件、单件工艺、integration与需求。新增纯读投影不读成本、不调用模型、不重复解析CAD大文件，不在首页列表生成。原后端字段/历史附件/其它行业能力保留。
- 候选/零件图形预览沿用2.1原CAD界面，不伪造矩形示意为原图；切换入口带当前项目和零件编号，宿主确实消费选择。所有新增按钮沿用inline-action/part-row-action，输入使用既有样式，文本转义。

## 操作与状态

- 包装3.1原整合分析动作只读取/核对方案与部件，不连带生成参数或工艺；主操作采用方案并进入排模。
- 采用方案后进入排模时，既有integration设置写接口可只准备缺失的开料尺寸输入；不调用参数/工艺模型、不填价格或工时、不伪造人工尺寸确认。自动几何模式关闭时不估算；原有已知尺寸不覆盖，估算来源如实保留。
- 包装3.2只保存排模/开料参数并进入工艺。成品必填参数留在需求页面及原后台，不以参数是否生成判断排模完成。
- 包装3.3补齐缺失工艺、汇总路线、采用路线与既有发送财务；复用同一prepare_route与只补缺口规则。不更改权限、财务交接或正式签字。
- 页签、会话标题、动作名称、前置提示与完成状态统一包装口径；非包装保留原三步骤和操作。编号、stage/view/action ID不变。计算只在第4阶段，不新增一键贯通按钮。
- 3.1完成依据为已选方案+有业务件；3.2为有效开料输入且关联用量完整（无排模走同一余量规则）；3.3为路线存在且原确认条件满足。缺失/未选方案/非法配置不能冒充完成。
