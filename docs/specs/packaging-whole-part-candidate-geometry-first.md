# 包装 DWG 整件识别：几何先组候选、模型只判语义（2026-09-24）

## 0. 为什么需要替换当前接法

`packaging_parts.extract()` 输出的是连通分量筛选结果，不是业务零件。当前业务件绑定仍以名称锚点到单个 region 中心的距离为主；本地新增的 `packaging_part_visual_review._candidates()` 也只是拿最近 8 个**单个** region 做视觉复核。酒盒真图中 Qwen3.5 Plus 对贴牌、左盖面纸、底板均拒答；这说明安全拒答可用，但没有解决“一个业务件由多组不相连的图元组成”。

不能恢复已撤销的 `## 503` 样本规则（“至少三片、覆盖九成、左右镜像”等）；不能以酒盒应有 28 行为运行时目标。酒盒对照资料仅用于离线评分：当前本地推导 28 行中，与资料严格同名 17 行，其中长宽两轴 ±2 mm 的 7 行也不等于图元归属正确。

## 1. 正确的职责边界

1. **CAD 确定性层**从原始图元、图层/ACI、块路径、文字坐标、标注扩展点和版面位置构造“整件视图候选”。连通分量是底层图元组，不是业务件；候选可以由 1 个或多个分量组成，也可以有相互竞争的组法。候选必须有真实图元 ID、组件 ID、图纸坐标范围和形成依据。
2. **模型语义层**只读取候选的紧凑事实表 + 对应局部彩色栅格图，建议：哪条文字是件名/材料/图例，哪个已有候选组对应件名、哪组候选应作为同一业务件、左右/同族命名是否需纠错。模型必须可以拒答。**不发送 DXF 原文，不让模型自由输出图元 ID 列表或几何坐标。** 模型输出只引用程序先生成的稳定候选 ID。
3. **程序校验层**验证被引用的候选确实存在，成员均来自 DWG、同一视图/排版格或有明确跨视图关系，组内图层角色/刀线边界相容；不同业务件不得无说明地占用同一外轮廓。标注必须以扩展线目标点/标注线与候选的空间关系定位到这组图元，**全图出现相同两个数字不算尺寸证据**。模型置信度不替代以上校验。
4. **人工确认层**对歧义、缺名、缺边界、模型建议、镜像推断给出可查看的候选图形和证据。人工可以确认几何归属；确认归属**不等于**确认尺寸。业务正式绑定/正式尺寸只来自 CAD 可验证证据或有留痕的人工确认。模型建议可持久化作审计，但不能以 `bound` / `size_confirmed=true` / `verified_by_cad` 写入正式事实。

本 Spec 的“模型只建议、CAD/人工确认”的原则沿用 `packaging_semantics/model_assist.py` 的弱证据思想；不要求把零件逻辑硬塞进需求字段专用的 `PackagingAssistResult`。模型调用仍复用 `llm_client` 与全局模型设置，不新增独立 API key。

## 2. 整件候选契约

新增纯函数 `packaging_part_visual_review.build_part_view_candidates(cad_ir, geometry_parts)`，不访问网络、BOM、Excel、已审核金标或项目历史价格。返回稳定排序的候选列表，每行至少有：

```json
{
  "candidate_id": "稳定 ID",
  "view_id": "视图/排版格 ID",
  "component_ids": ["真实分量 ID"],
  "entity_ids": ["真实 CAD 图元 ID"],
  "bbox": [0, 0, 120, 80],
  "boundary_role": "cut|crease|partial_cut|v_groove|mixed|unknown",
  "name_anchor_ids": [],
  "dimension_refs": [],
  "evidence_reasons": ["同一视图", "刀线互补", "扩展线指向"],
  "geometry_status": "supported|ambiguous|insufficient"
}
```

- 输出既要保留必要的单片候选，也要生成有证据的多片整件候选；一个视图内两段外刀线未在端点完全接上，不得因此永远被拆成两件。不能靠“必须 ≥3 片”或特定坐标/尺寸/件名生成多片候选。
- 两个相邻业务件即使包围盒接近，也不能仅因距离近合并；图层、刀线边界、视图/排版格和标注都要作为反证。块路径非空时参与候选分组；本样图 INSERT=0 时不应假设有块。
- 对整体平移、实体遍历顺序、名称替换保持等变：相同几何关系应有相同成员集；不得靠图纸 SHA、酒盒件名、对照表尺寸或最终件数决定候选。
- `geometry_status=supported` 必须有可回查 CAD 证据；仅模型建议或仅名称距离最近最多为 `ambiguous`。候选集合不保证覆盖金标所有件；没有图纸证据的采购件须单独标待确认，不能造图形。

## 3. 标注归属契约

`dimension_rects()` 保留每条横/竖标注的来源实体/扩展点及组合理由。`_region_is_size_confirmed()` 或替代接口不得只比较长宽数值。至少同时核验：

- 标注两轴数值和候选外形相容；
- 标注的扩展点/见证点与候选外边界空间关联，且没有同样合理的竞争候选；
- 标注属于同一视图/排版格，不是另一件的相同尺寸标注；
- 用尺寸矩形推导的整件外形仍须有真实 CAD 刀线/轮廓支持，不能把标注框本身当刀线。

不满足时保留标注为候选证据，尺寸质量为 `bbox_only` 或 `needs_confirmation`；不得进入工艺/成本的已确认尺寸通道。

## 4. 模型建议契约

新增纯校验器 `packaging_part_visual_review.validate_model_suggestion(request, suggestion)`。`request` 含 §2 候选及当前 CAD 已确认字段；`suggestion` 仅允许：候选 ID、文字锚点 ID、`name|material|legend|unknown` 分类、建议名称/材料、理由、模型自报信心。输出闭集：`status=needs_confirmation|rejected`、`evidence_level=WEAK`、`candidate_id`、`alternatives`、拒绝原因和越权字段名。

- 不在候选集的 ID、跨视图乱并、候选组无真实图元、输出原始 `entity_ids`/`bbox`/`length_mm`/`width_mm`/`size_confirmed`/`bound` 等越权结论 → `rejected`；不能只因 ID 存在就接受任意组合。
- `忖纸→衬纸` 一类文本规范化只进建议/别名；图纸原文与 CAD 已确认字段原样保留。材料文字不能当件名，图例/标题栏不成为业务件。
- 被接受的模型意见依然是 `needs_confirmation`，不能直接修改正式 `geometry_binding`、`reference.length_mm`、`size_quality`、已确认名称/材料。模型异常、无 key、无合格栅格图时，候选仍可查看，归属未确认；**不得恢复旧的错误距离绑定**。
- 审计至少留 `candidate_id + CAD/规则版本 + 模型建议(模型名/时间/理由) + 人工确认(人/时间/决定)`；不落图像字节、完整提示词、DXF 原文、思维链或密钥。

## 5. 前后端接线与验收

`resolve_business_parts()` 应消费整件候选而非单片最近 Top8；一键解析和旧项目补推导同一路径。左侧业务清单与右侧原位置平面图展示当前候选组、构成图元、名称/尺寸证据及“待确认”状态；人工确认用既有写接口，仍保持业务件和几何分量两本账，不把候选图形冒充最终零件。模型调用预算上限只限制复核数量，**不许**把未审的其余件默认判对。

红测至少覆盖：2 个不相连分量组成 1 件、相邻另一件不得混入；整体平移/顺序/名称变化不改变成员；相同尺寸的远处或别件标注不能确认；模型输出伪 ID/真 ID 乱并/伪尺寸被拒；模型成功也只记弱建议；模型失败仍保留候选而不恢复错误绑定；图例/材料与件名分开。旧路径的读接口、人工绑定、下游尺寸门禁不能倒退。

离线评估应按**整张图**记录候选召回率、图元归属准确率、名称准确率、两轴尺寸误差、误自动确认率、人工待确认率，并按图纸划分训练/留出；至少增加第三张未参与规则设计的真实 DWG 才能宣称泛化。权威工作簿/BOM 只在离线评分代码读取，不进入生产解析。不能以“输出 28 行”或“两个面纸尺寸命中”作为通过条件。
