# 报价智能体强调控件改为悬浮选中态 Spec

状态：TDD Red，等待 DeepSeek 实现。

## 背景与目标

报价智能体工作台中，以下四处当前长期显示为蓝色底、白色字，视觉上持续呈现“悬浮/选中”状态：

1. 对话区标题右侧的 `AI` 徽标；
2. 当前“确认需求配置”步骤前的数字 `1` 圆点；
3. 快捷操作 `强行填满本步骤`；
4. 底部主操作 `确认，进入下一步`。

这四处需要统一改为有边框的常态样式，只在鼠标悬浮时显示深色底白字。调整仅限视觉状态，不改变文案、DOM 身份、点击事件、步骤状态或业务行为。

## 视觉状态

### 常态

- 背景使用白色到现有浅色品牌背景的柔和同色系渐变 `#FFFFFF → #F4F9FE`；
- 文字和图标使用 `--color-primary`（当前值 `#0067D1`）；
- 必须存在清晰边框，使用 `1px solid var(--color-primary-border)`；
- 不得继续使用 `--gradient-ai`、纯主色或其他深蓝作为常态背景；
- 不得使用 `border: none` 或零宽边框。

### 鼠标悬浮

- `AI` 徽标和步骤数字使用 `--color-primary-active`（当前值 `#004A9F`）作为深色背景；两个按钮按后续 `primary-button-blue-gradient.md` 使用 `#0057B8 → #004A9F` 深蓝渐变；
- 文字和图标变为白色；
- 边框颜色同步为 `--color-primary-active`，防止边缘残留浅色描边；
- 按钮仅在非禁用状态下响应悬浮，禁用态继续保留既有不可操作反馈。

### 状态兼容

- 当前步骤的数字圆点仍表达当前步骤，不改变 completed、pending、viewing 的状态逻辑；
- `AI` 徽标仍为徽标，不新增点击行为；
- `qaFillStep` 和 `btnNext` 的 `onclick`、id、可用性判断及文案保持不变；
- 图标颜色跟随文字颜色，不出现深底蓝图标或浅底白图标；
- 键盘焦点、禁用态和现有布局尺寸不得退化。

## 修改范围

- 允许修改：`确认需求解析结果.html` 中与上述四个目标直接相关的 CSS；
- 如确有必要，可为四个既有元素增加仅用于样式定位的 class，但不得重构 DOM；
- 不修改其他报价、配置、规则或技术工艺页面；
- 不修改 JavaScript 业务流程、API、后端、数据库、权限、历史数据或部署配置。

## 验收标准

1. 四个目标在未悬浮时都是浅色背景、品牌蓝文字、1px 品牌浅蓝边框。
2. 四个目标在鼠标悬浮时都是 `#004A9F` 深蓝背景、白色文字/图标和同色边框。
3. `强行填满本步骤` 与 `确认，进入下一步` 的禁用态不会被 hover 规则覆盖。
4. 四个元素的文案、id、点击处理、步骤推进和状态计算完全不变。
5. 其他 `.btn-primary`（例如设置保存、历史修改）不得因本需求被无意改色。
6. 新增 Red 测试转绿，仓库已有测试保持通过，`git diff --check` 通过。

## 非目标与授权边界

- 不统一改造全站按钮或徽标；
- 不修改品牌色 token 的既定值；
- 不执行 push、MR、merge、tag、Release、部署、服务启动或浏览器操作。
