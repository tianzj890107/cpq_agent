# 普通报价内完成六步（2026-10-28）

用户明确授权在 feat/poc-1030 编写 spec、红测及业务实现。该分支尚无 ytbz 的包装专用成本引擎，本批不跨分支搬迁整套引擎。

最终客户输入口径以末尾「客户仅提供规格」为准：内部参数由系统读取，先前手工成本与JSON参数块只保留为兼容路径，不作为客户必填内容。

## 可验收行为

- 普通报价页提供显式「本单直接报价」入口，同一张卡仍按 1 需求、2 成本确认、3 利润、4 其他加价、5 报价方案、6 输出报价单完成；不建立技术项目或派发工艺任务。
- 仅创建本单的销售经理可在第1步尚未确认、后续步骤尚未开始且没有未结任务时启用（允许页面自动开始第1步）；按卡片保存模式，刷新恢复。不修改全局第2步角色、原技术工艺流程或其他卡片。
- 第1步保存产品/选用编码（可空）、客户、规格材料全文、正整数数量。选用产品的参数允许带入，不能将盒型当作已有成品价。
- 第2步由销售经理填写并显式确认每件未税成本、币种和成本来源。允许已核实的手工成本；缺失、零、负数、NaN、无穷或无来源均拒绝。系统不猜成本。未经真实核实的演示值只能标为演示成本，报价单持续标记「演示报价，不用于正式交易」。
- 第3步显式输入毛利率（百分数，0≤r<100）；第4步显式输入每件未税其他加价、税率（0≤t≤100），不暗填默认值。
- 金额使用 Decimal，税前单价=成本/(1-r)+每件加价；先按人民币分 ROUND_HALF_UP 得到成交单价，再乘整数数量求未税合计；税额=未税合计×税率，分舍入，含税合计=未税合计+税额。币种沿用成本确认。
- 第5步服务器按已保存步骤重新计算方案，不信客户端传价；第6步完成后可下载报价单（Word），只包含商业信息，不包含内部成本、毛利与来源。导出只读取持久化已完成单，不信客户端文档或价格。
- 服务端串行校验步骤，禁止跳步。完全相同的重复确认幂等，修改已确认步骤拒绝，不回退进度。所有写入同一事务，锁卡防并发，失败整体回滚，真实操作者留审计。
- 原 step-done 入口不能伪造直接模式或绕过直接报价确认；权限响应与页面均按本单模式显示第2步归销售经理。

## 验收及限制

自动化使用受控存储与真实工作流命令测试六步完成、重复/乱序/失败回滚、来源与非法数值、权限隔离、服务端金额和 Word 的持久化来源；Node 检查页面入口、请求与恢复行为。成本不完整时不能声称六步完成。

示例：茅台酒盒，200×150×80mm，天地盖，配合间隙1.8mm，V槽；盖面纸180g铜版纸亮膜，底面纸180g铜版纸哑膜，盖灰板2.5mm，1000个。该规格仅为本批测试场景，不证明匹配该分支的成品主数据；成本仍须用户核实确认。

不包含提交、推送、MR、tag、Release、部署、启动服务或线上验收。

## 特定提示词与原「下一步」入口验收（用户追加，10-28）

- 第1步支持正文中的唯一 `【直接报价参数】{JSON}【/直接报价参数】` 参数块。JSON的 `1` 至 `4` 键分别对应需求、成本确认、毛利率及其他加价/税率，复用本Spec的同一校验，不调用模型猜测。
- 合法完整参数块在第1步准备本单直接模式及各步预填数据，但不自动确认任何步骤。客户仍可核对和修改本步未确认字段。
- 不需要另点「本单直接报价」或弹窗。页面原来的「确认，进入下一步」/「进入下一大步骤」从1到6逐步保存并确认；第2步显式展示提示词提供的成本来源、用途及确认状态。第5/6步展示服务器计算的方案，第6次确认才变成完成。
- 普通无参数块的提示词仍走原入口；不完整或非法参数块停在第1步说明缺项，不回退到旧电池匹配，不留半启用状态。参数块中的成本用途与来源在金额计算和Word中保留真实语义。
- 刷新恢复服务器已保存的当前步骤及提示词预填；已完成步骤只读回看，不能靠原上一步按钮回退工作流。未完成报价不能导出为完成单。
- 验收须实际执行原页面 `runStep1` 和 `confirmStep`，连续六次点击对应路径，核对真实业务命令持久化的六条完成状态与Word；不得只在测试里直接调用六次服务函数来代替页面入口验收。

## 客户仅提供规格的纯文字入口（用户最终口径，10-28）

- 验收原文只包含「茅台酒盒，客户是贵州茅台」及200×150×80mm、盖/底180g铜版纸亮/哑膜、盖灰板2.5mm、V槽、天地盖、酒盒/高档酒盒、间隙1.8mm和首批1000个。不得要求客户提供成本、来源、毛利、税率、演示声明或JSON。
- 这些明确包装特征触发客户需求解析，纯确定性提取并保留全部材料/处理原文；缺失、冲突或无效尺寸说明业务缺项。不把包装需求送进旧电池工作温度门槛。客户明确要求转技术工艺时保留原流程。
- 内部成本与利润、税率及加价均由只读系统数据提供。必须匹配同一成品的完整规格及数量口径，并取得当前有效、未删除的成品成本记录和适用的包装规则；记录价格/参数/规则ID及来源快照。不使用结构对比用的盒型standard_cost冒充订单成本，不读取电池规则作包装定价。
- 有完整有效依据时，第1步后按原下一步连续完成六步，无手工补内部字段；系统字段受服务端绑定，客户端不能把演示数据改成正式报价。未知或演示来源持续披露，不得伪造真实成本。
- 缺系统记录时仍可确认第1步客户需求，第2步明确列出系统缺口，禁止用0、常数或模型估计代替成本，不要求客户补内部参数，也不得把这种阻断宣称为六步完成。系统数据不可用与没有匹配记录分别说明。
- 验收包含：受控完整价库下真实Chrome纯文字输入+六次原下一步+Word及刷新；缺价库下真实Chrome确认第1步后在第2步显示缺口且按钮不可推进。真实系统只读取证，不修改主数据或线上业务记录。
- 本轮最初为新的本地修改，不复用上一轮push授权；10-29用户后续明确授权提交、双推以及将本次提交部署到34演示环境。
