# 报价图纸与技术工艺需求承接

报价（精准/快速）可上传图纸并持久化原字节、名称、大小、SHA及报价关联；不只存摘要、不把二进制塞入模型提示词/浏览器storage。快速报价复用已有DWG/DXF统一解析只提取匹配特征，文字路径仍可用。转精准/技术工艺保留原图、结构化需求、原文、报价会话与业务实例。

工程师打开已授权的报价任务时，服务端幂等创建/认回同一个技术项目，导入原始需求快照和全部附件，提交到待确认（不代确认、不代审核）。进入1.2，后续1.3及2.1权限原样保留；无图也可完成需求确认/审核，在2.1才要求上传。独立建项仍有1.1。首次在2.1补图不得使已批准需求回到1.1；已存在的权威图纸替换仍保留既有修订纪律。

附件传递必须校验任务权限、附件属于源报价或发起人未绑定上传，防越权/篡改SHA、非法base64/空文件/大小超限/路径穿越。报价任务不能使用任意客户端project_id；重开/并发同任务复用项目，已编辑/已审核需求不重新覆盖。读取失败如实重试，不新建丢失来源的项目。

前端使用原有上传与按钮风格；首页和会话上传均保存文件，刷新能恢复，快速工作区上传/转交同样保留文件。技术侧页面按来源需求状态定位，不自动解析；已有图直接选用，没有图才提示补传。保持原报价卡片不前进/不换持有人，回传仍认原卡。

本任务仅本地实现/隔离验证；不自动提交、推送、部署或写线上数据。先运行实际失败红测，再补实现。

## 本地验证（2026-10-14）

- 初始红测实际失败：缺任务承接服务、技术任务仍要求图纸、报价两端没有原件持久化；实现后覆盖持久化字节、越权、非法路径/base64、SHA损坏、跨会话引用、同任务重开、已批准需求保持、首次补图与权威图纸替换的区别。
- 追加红测实际失败：需求检查仍将缺图列作缺口；2.1上传会新建项目；旧任务关联重开会复制项目。修复后旧关联按任务号及来源报价会话复用，不覆盖历史审批。
- 原文件使用PG `cpq_quote_attachment`，单文件16MB、单任务20份。浏览器仅保留小引用，首页绑定失败不跳页；精准历史页读回引用，快速工作区展示已上传图纸解析按钮并复用原有解析接口，不把DWG文本交模型。
- 首次图纸在2.1当前项目区域有统一小按钮；不会新增技术卡片，不自动解析，不使原需求审批失效。独立创建和已有权威图纸替换保留旧门禁。
