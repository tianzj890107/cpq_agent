# 报价共用分区、行业只差字段与算法

2026-10-15。用户授权实现、提交双推、部署34验证。

## 契约

1. 包装回传后仍使用既有六步及分区；不创建 packagingQuotePanel，不新增包装盒型/成本卡片。旧 s2_packaging、s2_packaging_cost、s2_report 保留存档，不独立渲染。
2. 产品字段承载基础成本、材料/加工/其他费用、单位/整单成本、币种、成本状态与来源版本；技术参数承载实际内长宽高、材料、闭合方式等，不把盒型上下限冒充实际尺寸，不显示电池参数。
3. 第3步已有定价规则表编辑毛利率（百分数），明确区别成本加成率；第4步已有加价规则表编辑项目和元/只金额（含0），折扣/税率/数量在第5步已有字段编辑。沿用原表格、按钮和详情样式，不增加整包递归卡片。
4. 包装定价仍用既有服务端引擎，毛利率按成本/(1-毛利率)，无前端第二套金额算法。完整原始交接包与成本证据保留。成本不是销售价格，不自动覆盖人工售价/折扣/加价。
5. 页面渲染、刷新、切页及历史版本读取只恢复，不调用定价、不落库、不推进步骤。显式计算/保存才重算；保存不完成步骤、不产生正式版本。明确参数未填不能猜值，0值不可丢失。
6. 新成本回传保留商业输入并标记需要重算；旧成本定价结果不能当新结果放行。异步结果必须同时校验会话和成本版本，切换项目或新成本到达后丢弃旧响应。
7. 显式重算的草稿在原会话保存，刷新恢复；服务端读取已存第2步成本而非信任浏览器传成本，核验销售归属、步骤、成本指纹后在事务内计算和合并快照。保留原字段、会话与历史报价版本。
8. 第5/6步金额与同一引擎版本一致；历史报价版本放回既有历史报价抽屉，不在工作区另叠卡片；只读、导出仍可用。非包装行业结构和算法不变。

## 红测与验收

实际运行新增专项失败后实现。覆盖目录同构、行业字段、旧包兼容、恢复零计算、费用0值、税率/折扣/数量、陈旧结果、销售权限、成本防伪、草稿保存不推进步骤与刷新恢复。相关报价/回传/成本/文件回归、真实Chrome交互及部署后隔离PG验证；不覆盖历史项目作测试。
