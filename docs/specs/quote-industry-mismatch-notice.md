# 规格：报价工作台「行业与需求不一致」的软提示

状态：Spec + 红测（已实现）
红测：`tests/test_quote_industry_mismatch_notice_red.py`

相关规格：
`docs/specs/global-industry-registry-and-packaging.md`（行业注册表唯一事实源）、
`docs/specs/quote-agent-industry-alignment.md`（需求门禁按行业）。

---

## 1. 现场问题（实测）

现场会话里报价助手头部的行业下拉停在**「半导体」**，用户输入的却是包装需求
（数码天地盒 / 盖面纸铜版纸亮膜 / 灰板 2.5mm）。后果是整条链路按错误行业跑：

- 门禁按半导体三项校验（尺寸/应用范围/工作温度），包装需求一开始被卡
  「缺少：工作温度」（`docs/specs/quote-agent-industry-alignment.md` §1.1 记的就是这条）；
- 匹配把包装需求拿去查锂亚电池库；
- ④产品技术参数的表头会按行业换成盒型库的 20 列，而行数据仍来自产品参数值表
  （表头与行不同源，属 B 档 P6，本批不碰）。

**系统对「行业选错」这件事一个字都不说**：`确认需求解析结果.html:2311` `step1Intent()`
拿到意图识别结果后只管「信息齐不齐」，从不校验需求内容像哪个行业；
`cpq_industries.INDUSTRY_KEYS` 虽然是行业唯一事实源，但报价侧只用它渲染下拉。

### 1.1 本批边界

**只加提示，不自动改行业。** 自动切行业会在识别错时把用户带进更深的错误（而且改了行业
就等于换了整套门禁与参数口径，属于业务决策）。本批要求：检测到不一致 → 出一条提示气泡，
让用户自己决定要不要动下拉。**绝不修改下拉的选中值。**

---

## 2. 目标

1. 在行业注册表 `cpq_industries.py` 里定义各行业的**特征词**，并提供一个**纯函数**
   `industry_hint(text, industry)`：需求文本更像另一个行业时返回提示对象，否则返回 `None`。
2. `/api/step1/match` 的意图识别阶段把 `industry_hint` 一并返回（为空就不带）。
3. 前端 `step1Intent()` 收到 `industry_hint` 时出一条软提示气泡：说清「当前行业是什么、
   需求内容更像什么、请确认」，**不弹窗、不改下拉、不阻断流程**。

---

## 3. 接口契约

### 3.1 `cpq_industries.INDUSTRY_HINTS`（唯一事实源）

```python
#: 行业特征词：只用于「需求文本更像哪个行业」的软提示，**不用于自动切换行业**。
#: 取值口径 —— 客户在需求文本里真正会写的词（行业模板字段名 + 业务口语词）。
INDUSTRY_HINTS: dict[str, tuple[str, ...]] = {
    "semiconductor": ("晶圆", "静电吸盘", "温区", "陶瓷基体", "金属基座", "微孔",
                      "氦气漏率", "洁净度", "TTV", "平面度", "吸附力均匀性"),
    "battery": ("电芯", "正极材料", "负极材料", "标称电压", "能量密度", "DCIR",
                "直流内阻", "循环寿命", "日历寿命", "叠片", "VDA", "热失控"),
    "appliance": ("额定功率", "能效等级", "整机外形", "耐压测试", "接地电阻", "EMC",
                  "安规", "噪声限值", "待机功耗", "关键成型工艺"),
    "packaging": ("盒型", "天地盒", "彩盒", "礼盒", "酒盒", "刀模", "压痕", "开窗",
                  "灰板", "面纸", "覆膜", "烫金", "模切", "裱贴", "V槽", "内衬",
                  "每箱数量", "外箱尺寸", "卡板"),
}

#: 命中门槛：候选行业至少命中这么多个不同特征词，才允许提示（防误报）。
INDUSTRY_HINT_MIN_HITS: int = 2
```

要求：

- 键必须是 `INDUSTRY_KEYS` 的四个行业，一个不少、不多出未知键；
- 每行至少 8 个词，词必须是非空字符串、同一行内不重复；
- 四个行业的词集合两两不相等（不许把同一份词表复制四遍）。

### 3.2 `cpq_industries.industry_hint(text, industry=None, *, min_hits=None)`

纯函数：不联网、不读库、不调模型、**不修改任何全局状态**（尤其不改 `INDUSTRY_KEYS` /
`DEFAULT_INDUSTRY` / 入参）。

判定规则（必须逐条成立，保证确定性）：

1. `text` 不是字符串或去空白后为空 → `None`；
2. `industry` 用小写去空白归一化，未知/空 → `DEFAULT_INDUSTRY`（沿用行业表既有口径，不抛异常）；
3. 对每个行业统计**命中的不同特征词**（按该行业词表顺序，保持稳定）；
4. 候选 = 命中数最多的那个行业；命中数并列时取 `INDUSTRY_KEYS` 里靠前的（保证同样输入
   永远同样输出）；
5. 只有当 `候选命中数 >= min_hits`（默认 `INDUSTRY_HINT_MIN_HITS`）
   **且严格大于当前行业的命中数** 时，才返回提示；否则返回 `None`；
6. 候选行业 == 当前行业 → `None`（不自己提示自己）。

返回值（键集合必须恰好是这 6 个）：

```python
{
  "industry": "semiconductor",          # 当前行业键（归一化后）
  "industry_label": "半导体",            # 当前行业中文名
  "suggested": "packaging",             # 需求内容更像的行业键
  "suggested_label": "包装",             # 它的中文名
  "hits": ["天地盒", "灰板", "面纸", "覆膜"],   # 命中的特征词（按词表顺序）
  "text": "需求内容更像「包装」行业（命中：天地盒、灰板、面纸、覆膜），"
          "但当前选择的行业是「半导体」。请确认行业下拉是否需要调整；"
          "本提示不会自动切换行业。",
}
```

`text` 必须同时含 `industry_label` 与 `suggested_label` 两个中文名，并明确写出
**不会自动切换行业**。

### 3.3 服务端接线

`cpq_agent_server.py` 的 `_handle_step1_match()`（意图识别阶段）返回体新增可选字段
`industry_hint`：

- 命中时带 `industry_hint.industry_hint`（对象）；
- 未命中**不带该键**（或为 `None`），前端以 `.get()` 判空；
- 不得因为该提示而改变 `stage` / `missing` / 门禁结果（提示是旁路，不影响判定）。

### 3.4 前端接线

`确认需求解析结果.html` 的 `step1Intent()`（`:2311`）在拿到响应后：

- 若 `d.industry_hint` 存在，追加一条 AI 气泡显示 `d.industry_hint.text`；
- 该气泡用系统主色/普通 AI 气泡样式，不用警告橙色；
- **不得**给下拉赋值（`$('industrySelect').value = …`）或改写 `CURRENT_INDUSTRY`；
  读取当前值用于拼提示文案是允许的；
- **不得**阻断流程：提示之后该走的分支照旧（信息不齐 → 提示补参数；信息齐 → 继续匹配）；
- 不得重复刷屏：同一会话同一 `suggested` 只提示一次。

---

## 4. 禁止事项

- 不自动切换行业下拉的值；不因提示而改 `currentIndustry()` 的返回值。
- 不改 `industry_templates` 的模板、必填项、标签。
- 不改门禁口径（半导体/电池/电器三项、包装 10 项）。
- 不改匹配来源（本批不碰 `cpq_match`）。
- 不新增第三方依赖；不新增大模型调用（纯字符串匹配）。
- 不改 `INDUSTRY_KEYS` / `DEFAULT_INDUSTRY` / `LEGACY_*` 的既有语义。
