# 报价包装匹配结果提示文案

状态：Spec + 红测 + 实现（本地）
红测：`tests/test_quote_packaging_match_advice_copy_red.py`

## 背景

包装匹配没有统一总分阈值。`step1_match_packaging()` 返回 `threshold: null`，并用
`below_threshold` 承载 `needs_new_tooling`。报价会话随后把该结果交给通用
`showTechNewSuggestion()`，该函数在阈值为空时回退显示 70 分，于是可能出现“最高匹配分
79.4 分，低于 70 分”。真实判定可能是尺寸越界，分数不是拒绝原因。

## 规则

1. 包装提示按 `industry=packaging`、`needs_new_tooling` 和 `new_tooling_reason` 展示，
   不把 `below_threshold` 当作分数阈值判定，也不显示“低于70分”。
2. `size_out_of_range`：可以显示当前最高候选的分数，但必须明确说明尺寸超出盒型库适用
   范围、该候选不可确认为现有盒型，需要新制评估。分数是相似/匹配评分，不是准入门槛。
3. `no_box_type`：说明盒型库暂无可用盒型，需要新制评估；不得声称尺寸越界。
4. `all_rejected` / `no_confirmable_candidate`：说明现有候选均未通过盒型适用条件，需要
   新制评估；不得虚构具体失败维度。
5. 缺少匹配必填项时提示补充需求，不提示立即新增产品。
6. 包装任务仍保留“转交工艺确认”“新增工艺”操作和可继续选择近似候选的说明。不得更改
   候选评分、适用性判定、任务派发或其他行业逻辑。
7. 电池/半导体/电器等已有阈值匹配继续使用真实 `threshold` 与“低于阈值”文案。

## 验收

- 包装得分 79.4、原因 `size_out_of_range` 时，渲染文本说明尺寸越界和不可确认，不能出现
  “低于70分”。
- 包装 `no_box_type` 与 `all_rejected` 显示对应的原因语义，不误报尺寸越界。
- 非包装得分低于真实阈值时，继续显示真实分数与阈值。
- 原任务按钮、派发类型与候选操作不变。
