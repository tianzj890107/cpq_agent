# 技术工艺“组装与整合”操作按钮状态 Spec

## 背景

技术工艺智能体进入“工艺方案/组装整合”后，操作按钮的主次层级与用户当前任务不一致：上传、重新生成等重复动作常驻深蓝，底栏则始终把“确认工艺并发送财务”显示为主操作。用户尚未分析时，真正的主操作应是“开始整合分析”；分析结果已经生成后，主操作才应切换为“确认工艺并发送财务”。

## 范围

仅调整以下前端按钮的视觉状态与父子页面状态同步，不修改按钮文案、点击事件、禁用条件、分析/确认/派发接口或任何后端逻辑：

- `#aiUploadBtn`：上传整合图纸；
- `#aiGenerate`：生成或重新生成参数推荐、生成或重新生成组装工艺；
- 统一工作台底栏 `#techSecondary`：在 `process` 阶段代理 `#aiStart`；
- 统一工作台底栏 `#techPrimary`：在 `process` 阶段代理 `#aiToFinance`。

编辑、保存、确认参数推荐、确认组装工艺、移除图纸、添加/删除工序和“下一步”等其他按钮不属于本次范围。

## 视觉契约

### 上传与生成类按钮

`#aiUploadBtn` 和 `#aiGenerate` 不再使用 `primary start-parse-btn` 的常驻填充型外观。它们在可用常态必须为：

- 白色或既有柔和浅蓝渐变背景；
- 品牌蓝文字；
- 1px 品牌浅蓝边框；
- hover（仅 `:not(:disabled)`）才变为深蓝同色系渐变背景、白字、深蓝边框。

busy/disabled 时不得触发 hover，不得因调整 class 而丢失现有 spinner、`aria-busy` 或禁用反馈。

### 底栏分析前后的主次反转

“已经分析过”定义为当前 `process` 子页面真实状态同时满足 `status.has_params === true` 与 `status.has_process === true`；只上传图纸、只生成其中一项、分析正在运行或分析失败均属于“尚未完成分析”。是否已经人工确认不影响这一视觉切换，且不得用 `#aiToFinance.disabled` 代替分析完成判断。

- 尚未完成分析：`#techSecondary`（开始整合分析）为深蓝渐变白字的填充型主按钮；`#techPrimary`（确认工艺并发送财务）为白底/柔和浅蓝底、蓝字、蓝边框的描边按钮，即使它因业务闸门 disabled 也不改变角色归属。
- 已完成分析：两者反转；`#techSecondary` 变成白底蓝字蓝边框，hover 深蓝底白字；`#techPrimary` 变成深蓝渐变白字的主按钮。

父工作台必须从同源子页面获得明确、可观察的分析完成状态，并由现有 `syncActionBar()` 在 iframe 首次加载及后续状态变化时同步按钮角色。不得按按钮文案猜测状态，不得将状态永久写死在 HTML 初始 class 中。

## 状态样式

建议为统一工作台按钮引入可复用的显式角色 class（例如 `is-filled` 与 `is-outline`），由 `syncActionBar()` 切换；样式继续复用现有品牌蓝渐变 token：

- 描边常态：`--gradient-primary-soft` + 品牌蓝文字 + `--color-primary-border`；
- 描边 hover：`--gradient-primary-hover` + 白字；
- 填充常态：`--gradient-primary` + 白字；
- 填充 hover：`--gradient-primary-hover` + 白字。

禁用态必须继续不可点击，并且 `:hover:not(:disabled)` 不覆盖禁用表现。

## 验收标准

1. 上传整合图纸、生成/重新生成参数推荐、生成/重新生成组装工艺常态均为白底蓝字蓝边框，hover 才深蓝底白字。
2. 分析前“开始整合分析”填充，“确认工艺并发送财务”描边。
3. 参数推荐和组装工艺均生成后，两按钮主次视觉自动反转。
4. 只生成一项、busy 或失败时不得提前反转。
5. `#aiToFinance` 的参数确认、工艺确认闸门保持不变；分析完成但尚未确认时可以呈现主按钮角色，同时仍保持 disabled。
6. 所有既有按钮 id、代理点击、接口、流程和后端逻辑保持不变。
