# 技术工艺上下文小流程与 iframe 状态行 Spec

## 目标

技术工艺顶部继续保留五个大流程，但大流程 1 和 5 原本各包含三个内部阶段，应像大流程 3、4 页面内部已有的步骤按钮一样，在右侧工作卡片内提供可见、可点击的小流程按钮。同时删除 iframe 上方“1.1 创建 已就绪”一类没有业务价值的状态行。

## 删除加载/已就绪状态行

`mountStageFrame()` 当前在 iframe 前插入 `.tech-wb-state.has-frame`，先显示“正在加载本步页面…”，load 后改成“1.1 创建 已就绪”。整行删除：

- 不再创建 `.tech-wb-state.has-frame`；
- 不再创建或更新 `#techStageMessage`；
- iframe 直接占满右侧工作区剩余区域；
- iframe load 后仍执行 `syncActionBar()`，不能因删除文字状态行而丢失底栏代理同步；
- 缺项目、无权限、未知阶段等真正异常状态仍使用现有 `.tech-wb-state.error`，不能一并删除。

## 大流程 1 的小流程按钮

当当前内部 stage 属于大流程 1 时，在右侧卡片标题区域、与大流程 3/4 内部步骤按钮相同的位置显示。不得另起一条横向流程栏挤动顶部五大流程的位置：

1. `创建` → `requirement-create`
2. `确认` → `requirement-confirm`
3. `审核` → `requirement-review`

点击后必须复用父工作台 `applyStage()`，继续更新 URL、iframe、底栏、前进后退和真实进度；不得直接拼 iframe 地址绕过状态管理。无项目时沿用既有导航保护。

## 大流程 5 的小流程按钮

当当前内部 stage 属于大流程 5 时显示：

1. `汇总结果` → `summary`
2. `结果审核` → `report-review`
3. `发布并回传报价` → `report-publish`

按钮不显示 1.1/1.2/1.3 或 5.1/5.2/5.3 数字；内部 stage id、既有页面文件和九阶段前后流转保持不变。

## 其他大流程

- 大流程 2 只有“图纸解析”一个内部阶段，不显示冗余的小流程栏。
- 大流程 3、4 继续使用各自右侧页面已有的内部页签/步骤按钮，不在父壳重复生成一套相同按钮。
- 切换大流程或浏览器前进后退时，上下文小流程栏必须同步出现、更新或隐藏。

## 四组步骤控件统一视觉

以下四组步骤/页签选中态都不得使用深色底白字：

1. 顶部五大流程；
2. 大流程 1 的三个小流程按钮；
3. 大流程 3、4 页面已有的内部步骤/页签按钮；
4. 大流程 5 的三个小流程按钮。

统一选中态为白底、品牌蓝文字、1px 品牌蓝或浅蓝边框，可以使用轻微蓝色 focus ring，但不能使用 `#0067D1` 深色填充、深蓝渐变或白字。hover/focus-visible 时也不得把已选中项变成深色底。

完成态可以保留对勾或语义标记，但步骤按钮主体仍不得深色填充。非选中 hover 可使用柔和浅蓝背景。

## 验收

1. 页面不再出现“1.1 创建 已就绪”或任何“X.X … 已就绪”状态行。
2. 流程 1、5 各显示三个上下文小流程按钮，并能切换真实内部 stage。
3. 按钮只显示名称且处在与流程 3/4 内部步骤相同的卡片标题位置，不移动顶部五大流程。
4. 流程 2–4 不出现父壳重复小流程栏。
5. 上一步/下一步、URL/popstate、iframe、完成态和业务接口不变。
6. 四组步骤控件 active/hover/focus 均遵循白底蓝字蓝边框。
