# Spec：成本结果与已发布报告回传工艺经理/销售经理并续接报价

状态：Spec + 红测（已实现）
红测：`tests/test_tech_cost_report_handoff_continuity_red.py`

## 1. 问题

成本测算结束后的业务去向应是二选一：提交工艺经理做第 5 大步最终工艺确认/报告，或直接
回传销售经理继续报价。当前“退回工艺经理”被当成返工支线，待办固定打开 `process`；
“发送至报价”虽然存在桥接代码，但来源关联失败时会新建以技术项目号为会话号的孤立报价
卡片，且没有稳定传递完整工艺、参数与成本交接包。

报告发布后的销售回传也没有形成正常界面闭环：看板注册了动作，但发布页没有稳定可见的
业务按钮；动作复用 `/integration/send-to-quote` 并只传 note，没有携带已发布报告、版本、
审核和附件信息，也可能重复执行报价第 2 步流转。

## 2. 成本测算后的两个去向

### 2.1 提交工艺经理确认

- 成本确认后可“提交工艺经理确认”，创建真实待办并通知目标工艺经理；
- 任务必须携带技术 `project_id`、来源报价 `session_id/task_id`、参数、工艺、零件成本、
  组装成本、成本汇总、财务确认人与意见；
- 工艺经理领取后进入统一技术工作台第 5 大步（入口 `summary`），继续汇总、确认、审核和
  发布工艺评估报告，而不是退回第 3 大步重新建参数/工艺；
- 如果确实需要返工，应由第 5 大步明确退回第 3 大步，不能把正常提交确认与返工混为一条。

### 2.2 回传销售经理继续报价

- 成本确认后可“回传销售经理继续报价”；
- 必须优先回到原报价 `session_id`，完成报价第 2 步“工艺确认”，创建销售经理可领取的
  标准报价待办，进入第 3 步“定价-利润加成”；
- 回传快照至少包含产品/成品编码、报价技术参数、完整成本拆解、零件和组装成本摘要、工艺
  路线摘要、批量、确认信息与技术项目溯源；
- 销售领取后打开原报价 Agent 的同一会话，并从第 3 步继续；不得打开空白报价会话；
- 没有可靠来源报价时必须显式建立真实报价会话并保留技术项目反向关联，禁止用技术
  `project_id` 冒充不存在的报价 Agent session。

## 3. 报告发布后的销售回传

- 报告状态为 `published` 后，发布页必须显示可见的“回传销售经理继续报价”按钮；
- 使用报告语义明确的后端路由/服务，不让页面直接调用 `/integration/send-to-quote`；
- 回传必须在成本/工艺交接包基础上附带报告编号、版本、标题、审核人/时间、发布人/时间、
  发布范围、结论、风险、附件/导出入口和技术项目链接；
- 销售领取后仍进入原报价的当前下一步骤。若成本阶段已经把报价推进到第 3 步，报告回传只
  更新技术结果快照并通知/补充当前销售任务，不得把报价倒退、重复完成第 2 步或制造重复
  open 任务；
- 重复点击必须幂等：同一项目、同一报告版本、同一目标报价会话只产生一个有效交接结果。

## 4. 任务生命周期与来源关联

- 技术待办领取时带入的 `task_id` 必须沿统一工作台 URL 进入成本/报告页面，并在完成去向
  动作时用于关闭原 claimed 任务；
- 新任务 payload 必须保存 `tech_project_id`、`quote_session_id`、`source_task_id`、
  `source_task_no` 和业务结果版本；
- 正常完成后，旧的财务 claimed 待办不能继续滞留；重试不得创建多个 open 任务；
- 继续使用现有 `cpq_wf` 任务、消息、卡片、步骤快照和审计表，不另建本地任务系统。

## 5. 必须保留

- 成本确认、写入数据库、成本复核/返工能力；
- `tech_cost`、`tech_cost_return` 的历史任务兼容读取；
- 报价六步、角色权限、任务领取和消息机制；
- 报告汇总、审核、发布、版本和发布范围；
- 所有历史项目、报价会话、任务、成本、工艺、附件和审计数据；
- Agent 的显式确认门与 TechBoardRuntime/TechBoardBridge。

## 6. 验收标准

1. 成本页有清晰的“提交工艺经理确认”和“回传销售经理继续报价”两个去向。
2. 提交工艺经理产生真实待办，携带完整交接包，领取后进入 `stage=summary`。
3. 回传销售优先关联原报价 session，创建标准报价待办并从第 3 步继续。
4. 报价第 2 步快照包含参数、工艺和成本，不只是简短 note。
5. 报告发布页有可见回传按钮和专用报告回传接口。
6. 报告回传携带完整发布报告信息，并与成本交接包合并。
7. 已推进报价时再次回传报告不会倒退步骤或重复创建 open 任务。
8. 来源 claimed 任务完成，新旧任务、消息和审计均可追溯。
9. 不减少现有后端、Agent、成本、报告和报价能力。
