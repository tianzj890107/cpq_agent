# 技术工艺附件直传与会话能力按钮重排 Spec

状态：TDD Red，等待 DeepSeek 实现。

## 决策

技术工艺 Agent 不再使用输入框左侧“＋能力菜单”。附件入口统一采用报价 Agent 的交互：输入框
左侧显示明确的回形针附件按钮，单击立即打开原生文件选择器。

原菜单中的解析视图、导入已有 3D 模型、版本与校核审查、联网核验、校验修正不得删除，全部
迁到 AI 会话区现有的 `#techChatActions` 快捷按钮栏。

## 1. 附件入口

- 输入框左侧使用回形针图标按钮，按钮可访问名称为“上传附件”；不显示字符“＋”；
- 不使用 `aria-haspopup="menu"`、`aria-controls="ocCapabilityMenu"` 或展开态；
- 点击附件按钮必须在同一次用户点击链路中调用隐藏文件输入框的 `click()`，直接打开系统文件选择器；
- 文件输入支持多选，保留现有图纸与补充文档类型；
- 选择文件后复用既有技术工艺上传 service/API 和右侧看板刷新链路，不新增第二套上传接口；
- 上传进度、成功和失败继续进入既有任务进度/错误反馈；不得只显示文件名而不真正上传；
- `#ocFilesAction`“任务文件”入口继续保留，用于查看已经上传的文件，不等同于上传按钮。

## 2. 会话快捷能力按钮

下列五项从弹出菜单迁到 `#techChatActions`，具有稳定的 `data-tech-capability`：

| capability | 按钮文案 | 既有行为 |
| --- | --- | --- |
| `evidence` | 解析视图 | 导航右侧解析视图 |
| `import3d` | 导入已有 3D 模型 | 导航右侧 3D 导入视图 |
| `review` | 版本与校核审查 | 导航右侧版本/校核视图 |
| `modelLookup` | 联网核验 | 执行既有 `modelLookup` 动作 |
| `verify` | 校验修正 | 执行既有 `verify` 动作 |

- 这些按钮属于 AI 会话快捷操作栏，与 AI执行、上一步、下一步、转交等现有按钮并列；
- 仅在适用阶段显示/启用；现有 2.1 drawing 能力边界不得扩大；
- 视图类继续走既有 `boardNavigateView`，动作类继续走既有 `executeAction`；
- 不读取 iframe DOM，不以 CSS selector 模拟点击右侧按钮；
- 不复制3D、校核或联网核验业务逻辑。

## 3. 删除旧菜单壳

- 统一工作台 DOM 中删除 `#ocCapabilityMenu` 和 `role="menu"` 菜单项；
- 删除只服务于该菜单的展开、收起、Escape、点击外部关闭及定位代码；
- 删除只服务于该菜单的 `.oc-capability-menu` / `.oc-capability-item` 样式；
- 独立旧页面若仍复用既有能力入口，不得因此失效；本次产品决策至少必须覆盖统一
  `tech-workbench.html`。

## 禁止事项

- 不删除任何原菜单业务能力；
- 不把附件按钮做成点击后先导航到上传页面；必须直接出现原生文件选择器；
- 不新增第二套上传后端、文件存储或历史文件表；
- 不跨 iframe 查询或点击 `#fileInput`；
- 不改变允许上传的类型、大小约束、权限、项目绑定和安全校验；
- 不修改报价 Agent 的附件入口；
- 不修改本 Spec 或 Red 测试；
- 不执行提交、推送、MR、merge、tag、Release、部署或服务重启。

## 验收标准

1. 技术输入框左侧是回形针附件按钮，不再显示“＋”或打开菜单。
2. 单击附件按钮直接触发统一父壳隐藏文件输入框，支持多选。
3. 选择文件后复用既有上传链路，成功后任务文件和右侧看板刷新。
4. 五项非附件能力全部出现在 `#techChatActions`，能力名和既有分派语义不变。
5. 旧 `#ocCapabilityMenu` 及其统一工作台菜单接线、样式被移除。
6. 任务文件、结果入口、阶段显隐、Agent会话和右侧业务能力没有回归。
