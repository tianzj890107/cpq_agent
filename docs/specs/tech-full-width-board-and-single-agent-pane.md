# 技术工艺满宽看板与唯一 Agent 会话栏 Spec

## 目标

技术工艺统一工作台只保留父页面左侧 `#techChatPane` 这一处 Agent 会话宿主。右侧 iframe 只承载当前流程的业务看板，图纸解析与成本测算必须和其他流程一样占满右侧可用宽度，不再因为子页面原有双栏、`max-width`、左右 padding 或隐藏栏位而收窄。

## 唯一会话栏

- 删除工作台底栏“子页面板”按钮及其展开/收起行为。
- 删除 `.show-child-chat` 状态与所有依赖该状态的 CSS/JS；嵌入模式下 `.oc-agent-pane` 必须始终隐藏，不能由用户重新展开。
- 流程 2（图纸解析）、3（组装与整合）、4（成本测算）原子页面会话/说明面板所需的阶段上下文、提示和操作入口，接入父页面左侧 `#techChatPane`，不得复制出第二套可见聊天 DOM。
- 父会话栏在流程切换、iframe load、浏览器前进/后退时同步当前 stage 上下文；复用现有 Agent 会话、项目与任务标识以及既有业务接口，不重建会话、不丢历史消息。
- 流程 1（工艺评估需求）和流程 5（工艺评估报告）不增加“子页面板”内容或阶段附加面板。父级常驻 Agent 会话栏仍存在，但不渲染由子页面迁入的额外上下文卡。

推荐用显式的 `STAGE_AGENT_CONTEXT`（只包含流程 2、3、4）和 `syncAgentStageContext()` 更新父会话栏中的单一上下文区域；也可采用等价实现，但不得跨 iframe 搬运/克隆整块 DOM。

## 右侧业务看板满宽

仅在 `embed=1` 的统一工作台场景覆盖子页面布局，独立访问旧页面的布局不在本次变更范围内：

- iframe、子页面 `html/body`、`.oc-shell`、`.page-container`、`.oc-work` 和 `.center-panel` 均占满右侧容器可用宽度，`min-width: 0`，不得保留限制看板宽度的 `max-width` 或自动居中外边距。
- 隐藏 `.oc-agent-pane` 后，`.oc-work` 必须退化为单列（例如 `display:block` 或单列 grid），不能继续保留子会话栏的列宽和 gap。
- 图纸解析与成本测算的 `.center-panel` 使用 `width:100%` / `flex:1 1 100%`，视觉左右边界与流程 3 的右侧业务看板一致。
- 保留统一工作台规定的固定内边距即可；不得叠加子页面原有的 1200/1560px 上限、236/196/78px 两侧 padding 或额外双栏 gap。
- 不删除图纸解析、组装整合、成本测算的业务内容、页签或操作按钮；父壳底栏的既有按钮代理继续工作。

## 可访问性与异常处理

- 删除按钮后，键盘 Tab 顺序中不再出现“子页面板”。
- iframe 尚未加载、跨源不可访问或业务接口失败时，父 Agent 会话仍可用；同步函数应安全退出并沿用现有错误展示，不能抛出未捕获异常。
- 不改变九个内部 stage id、URL、前后步骤导航、项目/任务绑定、Agent 后端、模型路由或业务 API。

## 验收标准

1. 五个流程中都不存在可见或可操作的“子页面板”开关，嵌入页没有第二个 Agent/说明侧栏。
2. 流程 2、3、4 切换时，左侧唯一 Agent 会话栏能识别当前阶段并承载原子页面需要的上下文；流程 1、5 不出现附加子页面板内容。
3. 图纸解析、组装与整合、成本测算的右侧业务看板具有相同的可用宽度，图纸解析和成本测算不再收窄。
4. iframe load、刷新、前进/后退后，上下文与当前流程一致，会话历史、业务状态和操作代理不丢失。
5. 本次只修改前端壳层、嵌入布局与会话上下文接入，不改变后端逻辑和接口契约。
