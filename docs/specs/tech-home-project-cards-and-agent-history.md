# Spec：技术工艺首页项目卡片与 Agent 完整会话恢复

状态：Spec + 红测（已实现）
红测：`tests/test_tech_home_project_cards_and_agent_history_red.py`

## 1. 问题

技术工艺历史 Drawer 能通过带鉴权的 `/api/projects` 看到真实历史项目，但统一首页的
“我的清单 / 全部清单”没有可靠复用同一数据：当前首页使用未带登录凭证的裸
`fetch('/api/projects')`，且“我的清单”对 `mode === 'tech'` 明确跳过归属过滤。
因此真实历史项目可能只出现在 Drawer，不能像报价单一样从首页卡片重新进入。

即使从历史 Drawer 打开项目，左侧 Agent 也只请求 `/agent/meta`；后端只返回
`message_count`，没有可供界面回放的消息内容。项目业务数据虽然恢复，完整 Agent 会话
（用户消息、助手回答和工具轨迹）没有像报价 Agent 一样恢复。

## 2. 产品决策

### 2.1 首页清单

- 历史 Drawer、我的清单和全部清单必须以同一个真实项目集合 `/api/projects` 为事实源；
- 首页读取技术项目必须携带统一 CPQ 登录凭证，并对非 2xx 响应显式报错；
- “全部清单”展示当前账号有权查看的全部技术项目；
- “我的清单”只展示 `owner === 当前登录 username` 的项目；历史兼容归属继续使用后端
  已有 `owner` / `backfill_legacy_mine_owner`，不得用 localStorage 猜测；
- 同一历史项目必须能同时出现在“全部清单”和其所有者的“我的清单”，卡片都携带同一
  `project_id`，点击进入统一 `tech-workbench.html`；
- 列表读取失败必须显示真实错误，不能伪装成“没有数据”。

### 2.2 Agent 会话恢复

- Agent 会话按 `project_id` 持久化并读取；从首页卡片、历史 Drawer、刷新、前进/后退进入
  同一项目，必须恢复同一条完整会话；
- 增加只读的项目 Agent 历史读取能力，返回按时间顺序排列、可供前端渲染的历史事件；
- 至少完整恢复用户消息、助手文本以及已有工具调用/工具结果轨迹，不能只返回数量或最近
  一段纯文本摘要；
- 前端初始化时先读取并渲染历史，再允许继续在该项目会话中发送；重复初始化不得重复插入；
- 新消息继续写入既有 open-claude `SessionStore`，服务进程重建 `ProjectAgent` 后仍能恢复，
  不能把浏览器内存、DOM 或 localStorage 当作会话事实源；
- “新对话/从头开始”仍只在用户明确点击时执行，打开历史项目不得调用 `/agent/new`。

## 3. 必须保留

- 历史 Drawer 与统一首页都保留，不删除任何历史项目、会话、任务或附件；
- `/api/projects`、项目 `owner`、现有鉴权和写权限规则；
- 九阶段工作台、项目阶段恢复、`pageContext` 注入、看板业务数据及全部后端能力；
- Agent SSE `text / tool_use / tool_result / error / done` 协议；
- `/agent/meta`、`/agent/send`、`/agent/new` 的既有职责；
- 当前工作区内与本任务无关的 `报价首页.html` 卡片高度微调不得覆盖。

## 4. 实现边界

可以修改统一首页、技术 Agent 前端、Agent 路由和 `oc_agent` 会话序列化/恢复逻辑。优先复用
open-claude 已有 `SessionStore`，不得另建第二套浏览器会话库或迁移/清空历史文件。

历史接口必须只读、受现有项目鉴权保护，并对异常/旧格式消息做兼容规整；不得把模型系统
提示词、API Key、内部工作目录或其他秘密返回给浏览器。

## 5. 验收标准

1. 首页技术项目读取携带统一登录凭证，并检查 HTTP 状态。
2. “我的清单”按当前用户与项目 `owner` 严格过滤；“全部清单”展示全部可见项目。
3. Drawer 中存在的真实历史项目同时出现在对应首页清单卡片中，并以同一 `project_id` 打开。
4. 存在只读 `GET /api/projects/{project_id}/agent/history`（或语义完全等价的明确历史路由）。
5. 历史响应包含可渲染的有序用户、助手、工具调用和工具结果，不只是 `message_count`。
6. `agent-chat.js` 打开项目时读取并渲染历史，空会话才显示空态，失败时显示明确错误。
7. 页面刷新、Drawer 和首页卡片三种入口恢复同一项目时，历史不丢失、不重复。
8. 打开历史项目不调用重置接口；继续发送会追加在已恢复会话后。
9. 现有项目、Agent、九阶段、看板与后端能力守护测试不回归。
