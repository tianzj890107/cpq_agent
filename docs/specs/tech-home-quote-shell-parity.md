# 技术工艺主页与报价助手主页统一 Spec

状态：TDD Red，等待 DeepSeek 实现。

## 背景与问题

`报价助手`、`配置助手`、`规则助手`都在 `报价首页.html` 内切换模式，因而共享同一页面高度、左侧导航、主内容宽度和响应式行为。点击`技术工艺`时，当前代码却特殊跳转到 `/home.html`；该页面由 `tech_app/frontend/home.html`、`home.js`、`home.css` 和 `home-layout.css` 维护另一套主页壳，造成页面高度和左侧导航明显不一致。

## 目标

- 四个助手的主页必须共用 `报价首页.html` 的同一个 DOM 壳和同一套左侧导航，不再为技术工艺维护独立可见主页。
- 点击`技术工艺`与点击另外三个助手使用同一模式切换机制，只调用 `setMode('tech')`，不得整页跳转 `/home.html`。
- 技术工艺仍展示自己的引导语、上传图纸、上传需求文档、行业模板、我的/全部技术清单和技术待办；“内容一致”指结构、尺寸和交互位置与报价助手一致，不是把技术业务文案或数据替换成报价数据。
- 进入 `报价首页.html?assistant=tech` 必须直接恢复技术工艺模式，并保持相同主页壳。
- 历史书签或旧入口访问 `/home.html` 时，应兼容汇聚到 `/报价首页.html?assistant=tech`，不得继续渲染第二套主页。原查询参数中可安全保留的任务/项目身份不得丢失。
- 从统一主页创建技术项目或打开技术清单后，仍进入 `tech-workbench.html`，不得退回旧步骤页。

## 统一视觉契约

技术工艺模式必须直接复用报价主页现有元素，不复制近似样式：

- `.nav-container`、`#navCollapsed`、`#navExpanded`；
- 56px 收起导航、240px 展开导航及 100vh 高度；
- 消息、设置、登录按钮及其既有 id、顺序和行为；
- `.page-container`、`.chat-container`、`.greeting`、`.category-tags`、`.unified-input-card`、`.list-section`；
- 与报价助手相同的主内容最大宽度、上下间距、卡片高度规则和响应式断点。

技术工艺模式不得引入 `.home-nav`、`.cpq-nav-collapsed`、`.cpq-nav-expanded` 或 `.home-main` 作为另一套活动主页导航和布局。切换助手时不得重新加载页面，左侧导航展开状态和当前登录/消息状态不应被销毁。

## 路由与状态

- 顶部四个标签统一走 `tagToMode()` + `setMode()`。
- `tech` 必须存在于 `MODES`，初始化参数 `assistant=tech` 与点击标签得到相同结果。
- 建议切换模式时用 `history.replaceState` 或等价方式同步 `assistant` 查询参数，但不得造成刷新或新增无意义历史记录。
- 技术项目创建成功进入 `tech-workbench.html?stage=requirement-create&project=...`。
- 技术清单和待办继续遵守统一双栏工作台 Spec，不得顶层打开旧技术页面。

## 非目标与安全边界

- 不修改技术业务 API、数据库、权限、成本公式和审批流程。
- 不删除历史技术项目、任务、会话、附件或运行数据。
- 不重写技术清单的数据获取和创建逻辑，只把现有技术模式放回统一主页壳。
- 不为了视觉相似复制第三套导航；报价主页是唯一视觉事实源。
- 本需求不授权 push、MR、tag、Release、部署或服务操作。

## 验收标准

1. 依次点击报价助手、配置助手、规则助手、技术工艺，浏览器始终停留在同一个报价主页壳，不发生 `/home.html` 跳转。
2. 四种模式拥有完全相同的页面高度策略、左侧导航 DOM、宽度、图标位置、展开/收起和底部按钮。
3. 技术工艺模式正确显示其专属文案、上传槽、行业模板、技术清单和待办。
4. 直接打开 `?assistant=tech` 得到与点击技术工艺相同的页面。
5. 旧 `/home.html` 自动进入统一主页的技术工艺模式，不出现旧导航闪现或重定向循环。
6. 从技术模式创建项目、点击清单或待办仍进入统一双栏工作台，参数不丢失。
7. 新增 Red 测试转绿，上一轮统一工作台测试和仓库工作流测试保持通过。
