# Spec：整合参数归位第 3 大步，成本测算只保留成本页签

状态：TDD Red，等待 DeepSeek 实现。

## 1. 问题

统一工作台第 4 大步“成本测算”错误包含“整合参数”页签，并承载报价必填参数的智能补全、
保存和确认。第 3 大步“组装与整合”的“参数推荐”虽然生成第一版整机参数，却允许带着
缺失必填项确认并发送财务，界面还提示去成本步骤补齐。

这造成职责倒置：工艺经理在组装整合阶段看起来“推荐不出来”，必须进入成本测算后才出现
真正的必填项推荐；财务步骤混入了非成本业务。

## 2. 产品决策

- 第 3 大步“组装与整合”负责完整的整机参数推荐，包括报价参数字典中的必填项；
- “参数推荐”页签内保留初次生成，并接管现有智能补全、人工修改、保存和“确认参数已齐”；
- 第 3 大步发送财务前，参数推荐和组装工艺均须确认，且报价必填参数必须齐全并完成最终确认；
- 第 4 大步“成本测算”只包含“零件成本 / 组装成本 / 汇总”，完全移除“整合参数”页签、
  侧栏入口及其补全/保存/确认 UI；
- 复用现有 `/integration/params/autofill` 和 `/integration/params/finalize`，只把它们的界面归属、
  权限和流程闸门移回第 3 大步，不另建第二套推荐逻辑。

## 3. 第 3 大步参数推荐行为

1. “生成参数推荐”继续以需求、整合图纸和 2.1 零件为输入，生成整机参数、连接关系与 BOM。
2. 如果报价必填项仍缺失，“参数推荐”页签直接显示缺失数和缺失字段。
3. 用户可在本页执行“智能补全”；建议值只回填界面，仍需人工核对后保存。
4. 本页提供“保存补填”和“确认参数已齐”；确认时后端校验全部必填项。
5. 参数修改后应撤销旧的最终确认；重新确认针对当前版本。
6. 未完成参数最终确认时，不允许“确认工艺并发送财务”。错误信息必须指出缺失字段或需先
   确认参数，而不是让财务去补。

## 4. 第 4 大步成本测算行为

只保留：

- 零件成本；
- 组装成本；
- 汇总。

不得出现：

- “整合参数”页签或侧栏按钮；
- `crRenderParams`、`crAutofill`、`crFinalize` 等整合参数界面逻辑；
- 对 `/integration/params/autofill`、`/integration/params/finalize` 的调用；
- `params` 看板视图注册。

成本步骤继续只负责测算、确认成本、写入数据库、发送报价和退回工艺复核。

## 5. 权限与后端边界

- 参数生成、补全、保存和最终确认属于第 3 大步工艺职责，沿用技术工艺写权限，而不是
  `COST_ROLES`；
- 不删除现有 autofill/finalize 路由，不改变其数据结构，不迁移或清空历史参数；
- 历史上已保存的 `params_final` 与参数值继续有效；
- 成本接口仍保持财务权限；不得借本需求扩大成本数据写权限。

## 6. 验收标准

1. 父壳 `CHILD_TAB_PROXY.cost` 仅有 parts、assembly、total 三项。
2. cost-review.html/js 不再包含整合参数页签、入口、渲染、补全、保存、确认或 params 视图。
3. 第 3 大步“参数推荐”展示报价参数字典、必填完成度和缺失项。
4. 第 3 大步可调用既有 autofill/finalize，建议回填后由人保存并最终确认。
5. autofill/finalize 使用工艺写权限，不再声称属于 2.3 财务步骤。
6. `send_to_finance` 要求 `params_final` 且必填项无缺失；否则拒绝流转。
7. 成本测算、Agent、看板桥、历史项目和全部既有后端能力不回归。
