# 技术会话主操作样式与全零件批量工艺/成本 Spec

状态：Spec + 红测（已实现）
红测：`tests/test_tech_primary_quick_actions_and_bulk_part_analysis_red.py`

## 背景

技术工艺会话快捷动作当前全部呈白底描边胶囊，主要动作不突出；2.1 工艺推荐主要从单个零件
进入，用户容易误以为必须逐件点击。2.3 已经具有 `runCostReview → crRunAll` 的逐件成本加整机
汇总能力，但入口仍叫“逐件测算并汇总”，没有表达“一键完成全部成本”。

## 1. 快捷动作视觉层级

- `#techChatActions` 继续使用报价快捷动作的胶囊体系；
- 当前阶段的 AI 执行、主要操作及本 Spec 的批量主操作使用报价 `.quick-action-btn.primary` 同级样式：
  系统蓝色渐变、白字、无普通描边；
- 上一步、下一步、转交、次要操作、附件和失败重试保持白底描边；
- primary 的 hover、disabled、focus-visible 必须清晰，disabled 不能仍像可点击；
- 主色必须引用现有 `--gradient-primary` / `--gradient-ai` 等统一 token，不写新色值。

## 2. 一键生成全部零件工艺推荐

在 2.1 drawing 阶段及零件清单看板提供明显入口：

`一键生成全部工艺推荐`

语义化动作名固定为 `runAllPartProcesses`。

- 必须复用既有单零件 `POST /api/projects/{project_id}/parts/{part_id}/process` 和任务轮询；
- 不新增批量后端路由，不复制 `services.process` 算法；
- 默认只处理尚无工艺推荐的零件，已经成功的结果不重复调用模型；
- 用户明确选择“重新生成全部”时才允许覆盖已有推荐，并需要确认；
- 批量编排采用受控串行，避免一次同时发出 N 个模型调用；
- 每个零件显示 running/succeeded/failed，整体显示 `完成数/总数`；
- 单个零件失败后继续处理其它零件，最后汇总成功、失败、跳过清单；
- 重试只处理失败或仍缺失的零件；
- 使用既有任务事件协议，动作采用 `deferred: true`，点击后立即回执，后台继续运行；
- 完成后刷新零件清单、工艺结果和父壳进度，不要求用户逐个打开零件。

## 3. 一键测算全部成本

2.3 cost 阶段主入口统一显示：

`一键测算全部成本`

继续使用现有动作名 `runCostReview` 和既有：

`crRunAll → crRunParts → crRunAssembly → 汇总`

- 不新增第二套成本编排或成本算法；
- 继续按零件受控串行，零件完成后计算整机并汇总；
- 保留核算批量、说明、确认成本及财务流转；
- 在会话主操作和右侧成本看板都使用同一用户文案；
- 继续通过任务进度反馈批量执行状态。

## 4. 入口与状态

- 会话栏的批量工艺和批量成本按钮都必须是 primary 蓝色主按钮；
- 不满足前置条件时禁用并提供原因：未完成图纸解析、没有零件、正在运行、权限不足；
- 禁止用户重复点击启动两个相同批次；
- 单零件“工艺推荐”入口继续保留，用于查看、编辑和单件重算；
- 单零件成本工具继续保留，用于复核和定点重算；批量入口不是删除精细操作。

## 禁止事项

- 不新增批量工艺或批量成本后端算法；
- 不并发轰炸模型接口；
- 不静默覆盖已有成功结果；
- 不因一个零件失败而丢失其它已成功结果；
- 不删除单零件入口、人工编辑、确认和审批能力；
- 不读取 iframe DOM 或模拟点击子页面按钮；
- 不修改本 Spec/Red 测试；
- 不执行提交、推送、MR、merge、tag、Release、部署或服务重启。

## 验收标准

1. 技术会话当前主操作呈报价式蓝色主按钮，其余操作保持描边层级。
2. 2.1 会话与零件看板均有“一键生成全部工艺推荐”。
3. 一次点击可串行覆盖所有缺失工艺的零件，并显示逐件与整体进度。
4. 失败可汇总、可只重试失败项，成功结果不被清空。
5. 2.3 会话和看板均显示“一键测算全部成本”，复用现有 `runCostReview/crRunAll`。
6. 单零件工艺、成本以及人工编辑/确认入口保持可用。
7. 新增 Red 测试转绿，既有看板、长任务、成本和快捷栏测试通过。
