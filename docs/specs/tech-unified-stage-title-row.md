# 技术工艺五步统一标题行与分步骤位置 Spec

## 目标

右侧每个大流程只显示一条统一业务标题行，左侧标题固定为：`工艺评估需求`、`图纸解析`、`组装与整合`、`成本测算`、`工艺评估报告`。

标题不得拼接项目名称、设备/总成名称、内部编号、文件名、动态报告标题或阶段编号。项目名称只在最上方“当前项目”区域显示。

## 标题行净化

以下内容不得出现在统一标题行：

- `创建中`、`就绪`、`读取中…`、`初稿` 等状态徽标；
- `2.3`、`1.1` 等编号；
- “图纸解析与工艺评估需求单”“2.3 成本测算 · 整机总成”等旧动态标题；
- `对话.svg` 等文件名；
- “不是位图”“只能读 PNG/JPG…”等错误或提示正文。

真实状态和错误不能删除：状态可进入内容区提示组件，文件格式错误继续显示在 Agent 对话/业务内容区，但不能与标题排列在同一行或改变固定标题。

## 分步骤统一位置

所有分步骤/页签都放在统一标题行右侧、同一水平线并右对齐：

- 流程 1：`创建 / 确认 / 审核`；
- 流程 2：没有额外分步骤，右侧为空；
- 流程 3：`整合图纸 / 参数推荐 / 组装工艺`；
- 流程 4：保留成本页面现有内部页签并移动/代理到标题行右侧；
- 流程 5：`汇总结果 / 结果审核 / 发布并回传报价`。

流程 1、5 不再把分步骤放在标题上方；流程 3、4 不再放在标题下方。iframe 子页面不得保留第二份重复可见标题、状态徽标或页签。

推荐父壳 `#techContextHeader` 作为唯一标题宿主，并对流程 3、4 的子页面页签做同源代理；也可以通过公共嵌入协议渲染同一组件，但最终只能有一条可见标题行和一组可见页签。

## 交互与样式

- 流程 1、5 的 stage 切换继续调用父壳 `applyStage()`。
- 流程 3、4 的代理按钮转发到子页面既有页签/状态函数，不复制业务逻辑。
- iframe load、子页面重新渲染、popstate 后标题和 active 页签同步。
- active 页签为白底、蓝字、蓝边框，hover/focus 不得深色填充。
- 标题行使用 flex + `justify-content:space-between`，页签右对齐；窄屏允许页签横向滚动。

## 验收

1. 五个大流程分别只显示指定固定标题。
2. 状态、文件名和错误正文不进入标题行。
3. 流程 1、3、4、5 的分步骤均处于同一标题行右侧；流程 2 右侧为空。
4. 子页面不再显示重复标题、状态徽标或第二份页签。
5. 点击、active 同步、URL、业务状态和后端接口不变。
