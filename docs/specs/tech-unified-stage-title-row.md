# 技术工艺五步统一标题行与分步骤位置 Spec

## 目标

右侧每个大流程的大标题名称固定为：`工艺评估需求`、`图纸解析`、`组装与整合`、`成本测算`、`工艺评估报告`。

统一要求只针对“大标题的名称”，不要求删除状态、文件、错误和业务提示信息。

## 大标题与状态信息

- 大标题文字本身必须严格使用上述五个固定名称，不能由旧动态标题取代，例如不能继续把“图纸解析与工艺评估需求单”或“2.3 成本测算 · 整机总成”作为大标题。
- `创建中`、`就绪`、`读取中…`、`初稿` 等状态允许继续显示，也允许作为独立状态徽标与大标题处于同一标题栏。
- `对话.svg` 等文件名、格式限制、“不是位图”等错误和提示允许按原业务位置继续显示，不要求迁移或删除。
- `1.1`、`2.3` 等内部编号可以继续用于程序状态、导航和其他必要业务信息，但固定大标题文字中不添加编号。
- 项目、设备/总成和文件名称仍可在各自业务信息区显示；最上方“当前项目”区域继续显示项目名称。

实现时应把固定标题节点与状态/提示节点分开，避免状态刷新覆盖标题文字；但不限制这些节点在视觉上位于同一行还是内容区。

## 分步骤统一位置

所有分步骤/页签都放在统一标题行右侧、同一水平线并右对齐：

- 流程 1：`创建 / 确认 / 审核`；
- 流程 2：没有额外分步骤，右侧为空；
- 流程 3：`整合图纸 / 参数推荐 / 组装工艺`；
- 流程 4：保留成本页面现有内部页签并移动/代理到标题行右侧；
- 流程 5：`汇总结果 / 结果审核 / 发布并回传报价`。

流程 1、5 不再把分步骤放在标题上方；流程 3、4 不再放在标题下方。iframe 子页面不得保留第二份重复的大标题或页签，但原有状态徽标和业务提示允许保留。

推荐父壳 `#techContextHeader` 作为唯一标题宿主，并对流程 3、4 的子页面页签做同源代理；也可以通过公共嵌入协议渲染同一组件，但最终只能有一条可见标题行和一组可见页签。

## 交互与样式

- 流程 1、5 的 stage 切换继续调用父壳 `applyStage()`。
- 流程 3、4 的代理按钮转发到子页面既有页签/状态函数，不复制业务逻辑。
- iframe load、子页面重新渲染、popstate 后标题和 active 页签同步。
- active 页签为白底、蓝字、蓝边框，hover/focus 不得深色填充。
- 标题行使用 flex + `justify-content:space-between`，页签右对齐；窄屏允许页签横向滚动。

## 验收

1. 五个大流程的大标题文字分别使用指定固定名称，状态变化不能覆盖这些名称。
2. 状态徽标、文件名、错误和提示正文可以继续按业务需要显示，包括显示在标题栏的独立区域。
3. 流程 1、3、4、5 的分步骤均处于同一标题行右侧；流程 2 右侧为空。
4. 子页面不再显示重复大标题或第二份页签；不以此为由隐藏状态和业务反馈。
5. 点击、active 同步、URL、业务状态和后端接口不变。
